The standalone `apps/srtop` crate uses the existing SDK, sessiond, Unix security and SSH bridge. Its five semantic nodes are Surface, Column, heading, read-only status and an empty PID/Name Table backed by a zero-item model. There is no collector, Terminal node or process-changing handler. An explicit local `--smoke-fixture` SIGUSR1 trigger changes the Surface label and heading in one ordinary transaction.

The generic macOS production client is unchanged. A native integration test, the app-specific `bash apps/srtop/test.sh` entry point, and required app build/test lines in CI and pre-push cover fresh checkouts without silently skipping a missing binary. The existing examples and dependency lockfiles remain unchanged; the new app has its own lockfile.

References: authoritative D1 §§6–8, 12, 22, 29 and D2 T9–T11, T16, T21. Existing APIs were checked at the base revision. No new OS process API, protocol, widget semantics, transport or runtime capability was introduced. The SDK has no TextBuilder/TableBuilder `read_only` convenience method, so the app uses existing `ui.set(..., READ_ONLY, true)`.
