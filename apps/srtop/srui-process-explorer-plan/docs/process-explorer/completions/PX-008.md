### Definitions the checks rest on

- **Synchronized**: the client holds the session's revision — in Rust, the catch-up snapshot `0 → r` with `r` the session's current revision has been received after `ServerWelcome`; natively, revision 1 is applied and the table is rendered.
- **App UI mutation**: a `Transaction`, the only message that changes a client's replica (§12.1), the §19.2 UI class.
- **Control traffic**: what the runtime's own `logical_class_for_server_envelope` classes `Control` — `ServerWelcome`, `ServerResumeOk`, `ServerResyncRequired`, `ServerHandshakeRefused`, `ServerEventAck`. It is counted and reported, never assumed absent; resource and terminal messages would be application traffic and fail the check.
- **The window closes with a canary**: the `update_title` fixture (Rust) or the `--smoke-fixture` SIGUSR1 retitle (native) commits one known transaction after the observation. Transactions arrive in commit order, so it must be the first transaction after synchronization, and its arrival proves the client was still receiving.

## Limitations

- The live evidence is a container on Docker Desktop's Linux VM; no separate physical Linux host was available to this gate, and `run.sh ssh` against one is documented rather than exercised.
- The frozen-source window is three seconds of ticks; a defect that published only after a longer quiet period would escape it.
- The process-control audit's blind spots are listed in the release record: dependency internals beyond their imports, the arguments of a dependency's raw `syscall`, which code reaches the imported `kill`, `waitpid`, `waitid` and `syscall`, the debug-only binary, Cargo configuration outside the package, and token rather than type matching.
- The scenario's picture is AppKit's rendering of the test host's window, because a `swift test` host's windows never reach the window server (a `screencapture -l` of one is blank white); the launcher's picture is the window server's own image of the production client.
- `ProcessExplorerDevboxScenarioTests` needs Docker and runs only through `r0-scenario.sh`; elsewhere it reports itself skipped, which is not a pass, and CI does not run it.
- Observed, outside this gate: `SSHTransportLiveIntegrationTests` sends its first activation without waiting for `isEventDispatchEnabled`, the race the new same-client test hit once; it passed in every run here.
- No push, pull request, tag, follow-on ticket, or self-declared independent verification.
