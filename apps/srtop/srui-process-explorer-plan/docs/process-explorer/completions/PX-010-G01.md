## 1. Objectives & Scope

Ticket `PX-010-G01` establishes early live collection scale qualification, progress telemetry, and resource budget validation for SRUI Process Explorer (`apps/srtop`).

### Core Deliverables
1. **`SyntheticProcessSource` in `apps/srtop/src/source.rs`**:
   - Deterministic 64-bit XorShift* PRNG seeded with `0x5CA1_AB1E_DEAD_BEEF`.
   - Four realistic process tiers: Daemons, Persistent Services, User Apps, Ephemeral Workers.
   - Pareto/power-law CPU% distribution (88% idle, 9% light 1-5%, 2.8% active 5-50%, 0.2% heavy 100-400%).
   - Log-normal resident memory distribution (kernel threads 0 B, daemons 256 KiB - 4 MiB, user apps 16 - 256 MiB, services 512 MiB - 4 GiB).
   - Distinct `CreationToken::Opaque(format!("scale-{}-{}", pid, start_tick))` minted on every churn cycle, proving that recycled PIDs do not alias with dead instances.
   - Controllable churn fraction (default 2% per tick).
2. **CLI Options in `apps/srtop/src/main.rs`**:
   - `--scale-source <COUNT>` and `--scale-interval-ms <MS>`.
   - Strict mutual exclusion with `--fake-source`, `--live-source`, and `--procfs`.
   - Bounded argument validation: count clamped [1, 100000], interval validated [50 ms, 60000 ms].
3. **Comprehensive Integration Test Suite in `apps/srtop/tests/scale_test.rs`**:
   - 1,000-row scale qualification under continuous 5% churn, CPU sorting, filter querying (`"worker | postgres"`), clearing, and selection persistence.
   - 10,000-row throughput benchmark: 5 refresh cycles completing well within the 3.0-second budget, journal transactions strictly bounded by `DEFAULT_MAX_FRAME_SIZE` (16 MiB), and constant UI node count (27 nodes).
   - 100,000-row architectural boundary probe: verifies strict enforcement of `MAX_PUBLISHED_ROWS` (100,000 ceiling), excess row eviction/truncation, and absence of unbounded memory growth.
   - Concurrent telemetry progress: `model_range` requests under high refresh rate.
   - Deterministic RTT envelope test: [0, 100, 300, 600 ms] latencies over in-memory `DelayedDuplex`.
   - Anti-coalescing proof: confirms structural model operations (`model_update`, `model_delete`, `model_reset_range`) are never coalesced or dropped.
   - Finite resource caps and stale filter generation rejection.
4. **Native macOS AppKit Verification in `client-macos/Tests/SRUITests/ProcessExplorerShellTests.swift`**:
   - `@Test @MainActor func largeCollectionRendersNativelyAndPreservesSelectionUnderChurn()`: runs 1,000 synthetic rows over real SSH (`--scale-source 1000 --scale-interval-ms 500`).
   - Verifies native `NSTableView` row count, column headers, valid cell string values, and selection anchored to `ItemId` preserved across active multi-cycle server churn.

## 4. Architectural Limits & Boundaries

1. **100,000 Rows Probe**:
   - The 100k-row test probe verifies the engine's hard architectural caps (`MAX_PUBLISHED_ROWS = 100,000`). It demonstrates that excess records are evicted or truncated cleanly without memory exhaustion.
   - This test establishes upper safety bounds and is deliberately documented as an architectural probe, not a claimed interactive single-client target.
2. **Process Control Integrity**:
   - `SyntheticProcessSource` strictly adheres to the process-control security boundaries defined in `PX-008`: no process spawning (`fork`, `exec`, `Command`), no signal dispatch (`kill`), no raw syscalls, and no unauthorized package dependencies in `apps/srtop/Cargo.toml`.
