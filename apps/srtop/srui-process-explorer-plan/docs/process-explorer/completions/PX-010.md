## Design

- **Responsive typing and server-authoritative filtering (§22.6).** Local typing, caret movement, and IME composition remain immediate in the native AppKit `NSTextField`. The server receives committed text changes via `TEXT_EDIT` events, filters the rows server-side, and publishes the resulting rows and status line atomically.
- **Inert grammar and bounded parsing.** The filter query parser splits on `|` into disjunctive OR terms. Input is capped at 512 bytes, and at most 16 terms are parsed. Strings are folded with Unicode case folding. Characters are sanitized to inert plain text. Zero regex backtracking, zero shell execution.
- **Monotonic generation tracking and stale result rejection.** Each query update increments a monotonic `FilterGeneration` (`u64`). Edits stage a filter and update the filter status to show the pending query (`Pending filter (gen N): ...`). When the query commits, the filter status displays committed counts (`Committed filter (gen N): "query" · M of N rows matched`). If a delayed or replayed event carries an older generation than what has already been staged or committed, it is rejected and discarded.
- **Process identity and selection stability.** `ProcessView` retains the complete `unfiltered_rows` vector server-side. When rows are filtered out and subsequently restored, they retain their exact `ItemId`s. The generic client's native `TableCollectionAdapter` anchors selection to `ItemId`, allowing the selection to follow matching rows as they move.
- **Frame and snapshot budgeting.** `FILTER_RESERVE_BYTES` (2048 bytes) is reserved in catch-up snapshot and frame budget calculations, ensuring the filter UI and status fit comfortably within protocol limits.

## Limitations

- Command line argument text is collected from `/proc/<pid>/cmdline` where readable; unreadable or inaccessible cmdlines fall back to process name matching only.
- Query grammar supports disjunctive OR terms (`|`) only; no boolean AND operator or nested grouping.
- Name and command matching is substring-based with Unicode case folding; no phonetic or fuzzy matching.
- Native table selection tracks visible items; items completely filtered out of the table do not retain native selection while absent, but re-selecting and clearing preserves exact item IDs.
