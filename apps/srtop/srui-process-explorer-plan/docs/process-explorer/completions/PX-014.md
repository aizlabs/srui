## Rules

### Lazy collection and identity

- **Read path.** The command line, executable and working directory are read only by the inspector's one detail worker (PX-013's `DetailReads`). The read is for the current target only, in the same request that reads its state and parent. They are tagged with `(ProcessKey, SelectionGeneration)` and dropped unless both still name the target. The scan never reads them.
- **Identity check.** `stat` is read before and after. Both must carry the key's `LinuxBootTicks` start time. Through a pinned directory, the kernel binds the handle to the instance (`fs/proc/base.c`). Read by name, two matching reads prove the PID named that instance throughout, because an ended instance never returns.
- **Re-reads and lifetime.** The arguments are re-read on each refresh that confirms the selected row, as the state is (PX-013). A change is published; an unchanged one publishes nothing (tested). They are held only in the current target's `Details`. A new selection, an ended target or a dropped view discards them. They are never persisted.

### Display: argv, not a shell command

- **Layout.** Line 1 is the header: `Command line (argv on the server, shown as text, never run): N arguments, B bytes`, with `at least` past the scan bound. An area with no final NUL adds a `rewritten` note. Then each argument gets its own line: `argv[i] · L bytes · <inert text>`. The last two lines are `Executable on the server: …` and `Working directory on the server: …`.
- **No shell form.** The view has no joined, quoted or "copy as command" form. The raw bytes are never written back into a row, the PX-010 command filter's text or a key. The live source still sets no filter command text.

### Scrub rules (display only)

- `\` → `\\`, so an argument that spells `\x1b` shows `\\x1b` and cannot pass for an ESC byte.
- `\n` → `\n`, `\r` → `\r`, `\t` → `\t`. Any other C0 control or DEL → `\xHH`. ESC → `\x1b`.
- C1 controls (U+0080–U+009F) → `\u{XXXX}`.
- These characters → `\u{XXXX}`: U+00AD, U+061C, U+180E, U+200B–U+200F, U+2028–U+202E (line and paragraph separators, bidi embeddings and overrides), U+2060–U+2064, U+2066–U+206F (isolates), U+FEFF, U+FFF9–U+FFFB, and U+E0000–U+E007F (tags).
- A byte that is not UTF-8 → `\xHH`.
- Everything else is shown as is: quotes, `$()`, backticks, `;`, `|`, other scripts and emoji.
- An escape is never split by a cut.

### Bounds and explicit truncation

| Bound | Value | When exceeded |
| --- | --- | --- |
| Arguments kept | 256 | counted: `… M more arguments not shown (B bytes)` |
| Argument bytes kept | 16 KiB | an argument that starts later is counted; one that straddles the bound is kept cut |
| Area scanned | 2 MiB | `at least N arguments, at least B bytes` |
| Path bytes kept | 4096 (`PATH_MAX`) | `Executable on the server (L bytes, first K shown): ……` |
| Display per argument | 1024 bytes | `argv[i] · L bytes, first K shown · ……` (K raw bytes) |
| Display per path | 1024 bytes | as above |
| Whole view | 8192 bytes | arguments that do not fit are counted on the `… more arguments not shown` line; the header, the "more" line and both paths have reserved room |
| Snapshot reserve | 10240 bytes | measured: the widest node encodes to more than half of it and to at most all of it |

Each cut note comes before the text it cuts, on the argument's own line. An argument cannot forge it, because its own newlines are escaped.

### States

| Arguments | Executable / working directory |
| --- | --- |
| read | read |
| `empty: the process was started with no arguments` | read |
| `none: the process has exited and is not yet reaped (zombie)` | the same |
| `none: a kernel thread has none` | the same; for an unprivileged reader `cwd` of a kernel thread is normally `permission denied` |
| `permission denied` (for example `hidepid`, or a mode-0 fixture) | `permission denied` (the ptrace read check; another account's process) |
| `unavailable` | `unavailable` |

The whole-record states are inherited from PX-013: loading, not provided, denied, unavailable, not shown, ended and refused.

### Native

- The node is a standard `RichText` with `read_only`. The unchanged generic client renders it as an `NSTextView` in an `NSScrollView`: `isEditable == false`, `isSelectable == true`, no automatic link or data detection.
- The text is plain: a string with no link attribute. Selection, Copy and the pasteboard are the platform's own (§22.5, §22.6). Nothing reaches the server.
- Paths are labelled "on the server". Nothing on either side resolves or opens them (§26). No handler was added: the PX-008 audit is unchanged and passes.

### No logging

- Raw arguments and paths sit behind `Sensitive`, whose `Debug` redacts them.
- Every production `eprintln!` formats exactly `"srtop: …: {error}"`, and nothing in production code prints to stdout or uses `dbg!`. `no_production_log_line_formats_a_value` audits this.
- The secret tests run the real handlers and worker in a child process with stdout and stderr captured whole, and assert the secret is absent. On every platform this uses the fake source; on Linux it also uses a live test-owned worker. The native test also captures `srtop`'s own stdout and stderr to a file and checks it for the secret.

## Limitations

- **One worker, no deadline (inherited).** A read now also reads `cmdline` (at most 2 MiB through an 8 KiB buffer) and two links, on the same single worker as PX-013's `stat` (`lc-debt` in `inspector.rs`). A wedged procfs read still holds it.
- **Re-read per confirmed sample.** The selected process's argument area is re-read on every refresh that confirms its row: up to 2 MiB per tick for a pathological process. Nothing is published unless the text changes.
- **What the kernel reports, now.** A process may rewrite its argument area. The view shows the current contents and flags an area with no final NUL. It cannot show the original arguments. An `exe` ending in ` (deleted)` cannot be told from a file really named so.
- **Bounded display.** Beyond 1024 bytes an argument is cut, and beyond 8192 bytes of view the remaining arguments are only counted. A very long single argument, such as a Java classpath, cannot be read whole in the view. The fixed native height (the generic `RichText` is at least 52 points tall and scrolls) shows about three lines at a time.
- **Copy is the platform's.** Copying copies the display text, escapes included, never the raw bytes. A copied argument that held a newline therefore holds `\n`. This is deliberate: the copied text is as inert as the displayed text.
- **Shared by the session.** Like the rest of the inspector, every client of one srtop session sees the last selection's command line.
- **Pinning is Linux-only.** Read by name (non-Linux, or a tree that is not a kernel procfs), the double `stat` check still refuses a PID reused during the read, but a tree that is not a kernel procfs has no instance binding at all, as in PX-005-G01.
- **No macOS live reader.** As in PX-013.
