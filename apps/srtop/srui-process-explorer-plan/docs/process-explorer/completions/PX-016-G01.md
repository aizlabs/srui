## Design reading

Read before implementing: §4 (inv. 3 presentation-only state is local, inv. 13 unknown required semantics fail explicitly, inv. 18 automation only through the normal event path), §7.2 (vocabulary and admission rule), §7.4 (common properties), §7.6 (standard events: Button → `ACTIVATE`, Toggle → `VALUE_CHANGED`, editors/collections have local behaviour), §7.7 (semantic input routing: the client reports what happened to which node, never raw input), §22.5 (focus and IME composition are local), §22.6 (IME marked text stays local; clipboard through the local text control), §22.7–§22.9 (collections, accessibility, semantic inspection), §26 (bounded decode, fail closed), §32 (suites). The design contains no keyboard-shortcut concept, and nothing in these sections contradicts the build: a shortcut is local input routing that produces the existing §7.6 events (or local focus), never a new event type, so the event model and §7.7 are unchanged. The decision to add one standard property was the user's.

## What was built

- **Property.** Standard registry property **31 `shortcut`** (namespace 0, `control_specific`, `value_type: string`) in `protocol/registry.yaml` and `PROPERTY_SHORTCUT = 31` in `protocol/srui.proto`. `./protocol/generate_proto.sh` regenerated `client-macos/Protocol/srui.pb.swift` and `client-macos/SemanticModel/RegistryTables.swift`; `server-rust/semantic-tree/build.rs` now asserts 31 properties. `spec/registries.md` §4.2 documents the property; `CLAUDE.md` names the new count.
- **Grammar (closed, canonical; identical in `server-rust/semantic-tree/src/shortcut.rs` and `client-macos/SemanticModel/Shortcut.swift`).**
  - `[primary+][shift+][alt+]<key>`, at most **32 bytes** (`MAX_SHORTCUT_BYTES` / `maxShortcutBytes`), checked before parsing. The longest valid value, `primary+shift+alt+page_down`, is 27 bytes.
  - `<key>`: one lowercase ASCII letter `a`–`z` or digit `0`–`9`, or one of `return`, `escape`, `tab`, `space`, `delete`, `up`, `down`, `left`, `right`, `home`, `end`, `page_up`, `page_down`, `f1`–`f12` (canonical only: `f01`, `f13`, upper case refused).
  - Each modifier at most once, in that order, so each combination has exactly one spelling and two shortcuts conflict exactly when their strings are equal.
  - `primary` is Command on macOS and Control elsewhere. **Every key except `f1`–`f12` requires `primary`** — stricter than "a printable key requires primary": bare editing/navigation keys (`return`, `delete`, arrows, `tab`, `space`) would otherwise compete with text editors, collections and the key-view loop exactly as a bare letter would.
  - Failure reasons (same wording in both languages): not a string, empty, too long, unknown token, duplicate modifier, misordered modifier, missing key, requires primary.
- **Decode (§26).** Rust `validate_decoded_shortcut` runs in `Property::try_from` (node records, `CREATE_NODE`, `BATCH_PROPERTY_SET`, event arguments, small records, model items) and on `SET_PROPERTY`; Swift `ProtocolDecoder.checkDecodedShortcut` covers the same pairs in the validating decoder and `validateDecodedShortcut` covers `Property(wire:)`/`StoreOperation(wire:)`. Error: Rust `ValueConversionError::InvalidShortcut` → `TxnError::WireError("invalid shortcut: …")`; Swift `ProtocolDecodeError.invalidShortcut` (`invalid_shortcut`) and `ValueConversionError.invalidShortcut`.
- **Apply (both stores, same order and codes).** Grammar again (`invalid_shortcut`), node-type admission (`shortcut_not_admitted`), and uniqueness within one Surface (`duplicate_shortcut`). Admitted: `Button` (dispatch `ACTIVATE` as a click), `Toggle` (flip and `VALUE_CHANGED` as a click), `TextInput`, `TextArea`, `List`, `Table`, `Tree`, `RichText` (local focus only, no event). The scope is the nearest `Surface` ancestor-or-self, or the root when there is none; a nested `Surface` is its own scope. Checked on `CREATE_NODE`, `SET_PROPERTY`, `BATCH_PROPERTY_SET` and a `MOVE_NODE` that changes scope; per operation, so exchanging two shortcuts clears one first. Swift skips the generic value-type check for `shortcut` so a non-string reports `invalid_shortcut` as Rust does. The uniqueness scan is O(nodes in the Surface) per shortcut-setting operation, marked `lc-debt` in both stores.
- **SDK.** `impl_shortcut_prop!` gives Button, Toggle, TextInput, TextArea, List, Table, Tree and RichText a builder `.shortcut(...)` (a `&str` or a parsed `Shortcut`), `shortcut`/`shortcut_of`/`get_shortcut`, `set_shortcut`/`clear_shortcut` and `op_set_shortcut`/`op_clear_shortcut`. `Shortcut`, `ShortcutBehavior`, `shortcut_behavior`, `MAX_SHORTCUT_BYTES` are re-exported from `srui-sdk`.
- **Renderer (`client-macos/RendererAppKit/ShortcutRouting.swift`).**
  - `AppKitShortcutBinding` maps a shortcut to `keyEquivalent`, modifier mask (`primary` → Command, `shift` → Shift, `alt` → Option), and for named keys the layout-independent key code.
  - Every Surface window's content view is a `SurfaceContentView` that asks the renderer's `ShortcutRouter` in `performKeyEquivalent(with:)` (and for unconsumed key-downs) before the view hierarchy. Matching requires exactly the binding's modifiers (Caps Lock, Fn and numeric-pad flags ignored); letters and digits follow the active layout.
  - Dispatch:
    - Button: the control's own target/action (`sendAction(_:to:)`, the path a click takes; `performClick(_:)` is never used).
    - Toggle: flip the checkbox state, then the same target/action.
    - Focus targets: `makeFirstResponder` on the field, text view, table or outline. No event.
  - Guards: no dispatch, and the event continues unchanged to the main menu and first responder, when the window is not key; when the first responder is an `NSTextInputClient` with marked text; when the node is disabled; or when the node or any ancestor is `hidden` or `collapsed` (all read from the committed semantic state).
  - Reserved macOS table (never bound; records `ShortcutDiagnostic.reserved` on the handle and logs through `RendererDiagnostics`): Cmd-Q, Cmd-W, Cmd-H, Opt-Cmd-H, Cmd-M, Cmd-Tab, Cmd-`, Cmd-comma, Cmd-C, Cmd-V, Cmd-X, Cmd-A, Cmd-Z, Shift-Cmd-Z, Cmd-Space, Ctrl-Cmd-F, Cmd-?. Cmd-`, Cmd-comma, Ctrl-Cmd-F and Cmd-? cannot be expressed by the grammar; they are listed for completeness.
  - Discoverability: tooltip `"<label or description> (⇧⌘R)"`, accessibility help `"<description>. Keyboard shortcut ⇧⌘R"` (also on the inner editor/collection view); both revert exactly to the pre-shortcut state when the shortcut is cleared or unbound.
  - `DirtyClassifier` classifies `shortcut` as `accessibilityOnly`, an in-place update.
- **Inspection (T35, `client-macos/Accessibility/Accessibility.swift`).** `SemanticNodeSnapshot.shortcut` (canonical) and `shortcutDisplay` (platform text, `nil` when reserved). A shortcut adds no advertised event type.
- **Generic shell.** `SRUIApplicationMenu` gains a standard Edit menu (Undo ⌘Z, Redo ⇧⌘Z, Cut, Copy, Paste, Select All), every item targeted at the first responder. Surface windows set `autorecalculatesKeyViewLoop` and `LayoutRenderer.mount` recalculates each Surface's key-view loop after every mount and remount.

## Limitations

- Byte identity of the shortcut event is proven at the interaction boundary: the shortcut and the click deliver the identical `SemanticInteraction`, and `SessionController` builds the wire event from that value alone, so the encoded events are identical for the same sequence/id/revision. A live socket session test of the same is not added.
- Tests drive `NSWindow.performKeyEquivalent(with:)`, `sendEvent(_:)` and `sendAction(_:to:from:)` directly with real `NSEvent`s: the test host never activates (`SurfacePresentation.concealed`), so `ShortcutRouter.isWindowKey` is a test seam and the main menu's nil-target routing through the key window is exercised by sending the matched item's action to the window's first responder.
- Bare `f1`–`f12` are admitted; a text view may consume some of them first (for example F5 `complete:`), which keeps editors in control as intended.
- Uniqueness scans the Surface subtree per shortcut-setting operation and the router scans mounted handles per key equivalent (`lc-debt` comments).
- Platforms other than macOS have display text (`Ctrl+Shift+R`) but no reserved table and no renderer.
