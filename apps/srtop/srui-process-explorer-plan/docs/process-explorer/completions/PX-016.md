## Gap investigation and the dependency on PX-016-G01

The first pass of this ticket, at PX-015 `a2d4b5e8`, found no generic shortcut contract. It stopped and committed nothing, as the ticket requires.

- **Design v0.6:** the words "shortcut", "key equivalent", "accelerator" and "hotkey" never appear. §22.5 makes focus and menu opening local, and says nothing about shortcuts.
- **Registry:**
  - property 5 `actions` was a passive string list;
  - property 28 `action_key` was an opaque server handler key;
  - `Menu` and `Toolbar` are deferred-tier.
- **Renderer:**
  - `.actions` was stored as accessibility metadata only;
  - the only key equivalent was Return on an `ActionRole.primary` button;
  - Menu and Toolbar nodes were refused as unsupported.
- **Client shell:**
  - the main menu held Quit only, with no Edit menu;
  - no code configured the key-view loop.

Writing a Process Explorer `keyDown` switch in Swift was forbidden. The bounded prerequisite **PX-016-G01** (platform-neutral semantic keyboard shortcuts) was therefore written and implemented separately, and verified at `ccc63f8f`. It provides:

- standard property 31 `shortcut`, in the grammar `[primary+][shift+][alt+]<key>`, where every key except F1–F12 needs `primary`;
- admission by node type (Button → `ACTIVATE`, Toggle → `VALUE_CHANGED`, editors and collections → local focus only);
- uniqueness per window-owning Surface;
- the macOS reserved table, and the key-window, marked-text and disabled/hidden guards;
- the shortcut in the tooltip, the accessibility help and the inspection snapshot;
- the client Edit menu and key-view-loop recalculation.

PX-016 now `depends_on` PX-015 and PX-016-G01. It uses G01 from srtop only. No G01 defect was found.

| ⌥⌘F | `primary+alt+f` | 26 | Filter processes | focus |
| ⌥⌘U | `primary+alt+u` | 51 | All visible users (user-filter reset) | `ACTIVATE` |
| ⌘F | `primary+f` | 43 | Find processes | focus |
| ⇧⌘G | `primary+shift+g` | 44 | Previous match | `ACTIVATE` |
| ⌘G | `primary+g` | 45 | Next match | `ACTIVATE` |
| ⌘1 – ⌘4 | `primary+1` – `primary+4` | 21–24 | Sort by PID, Name, Resident, CPU | `ACTIVATE` |
| ⌥⌘R | `primary+alt+r` | 41 | Restore default columns (column reset) | `ACTIVATE` |
| ⌘L | `primary+l` | 5 | Processes (table) | focus |
| ⌘I | `primary+i` | 60 | Command line and executable | focus |

- **Decisions:**
  - **Sort: per-button shortcuts ⌘1–⌘4.** Tab reaches a button only when macOS Keyboard navigation (Full Keyboard Access) is on, which is off by default. Without these shortcuts, sorting would be unreachable from the keyboard on a default system. The shortcuts follow the sort buttons, whose order the column chooser never changes, so ⌘1 is always PID whatever the column order.
  - **Inspect:** ⌘I focuses the inspector's selectable command line (PX-014). The inspector's four status lines are static text and are read by assistive technology in order. The inspector already follows the table selection.
  - **Reset:** no clear-filters control exists, and none was invented.
    - Focusing a text field selects its whole text, which is AppKit's own behavior and the same for Tab. So ⌥⌘F then Delete clears the filter, and ⌘F then Delete clears the search.
    - The two existing reset buttons get shortcuts: ⌥⌘U (All visible users) and ⌥⌘R (Restore default columns).
  - **Not bound:** Only my processes, Go to PID, the PID, PID-set, user and interval fields, Apply interval, and the twelve column hide/move buttons. They stay reachable by Tab, and buttons by Tab and Space when Full Keyboard Access is on. The ticket names none of them.
- **Reserved and conflicts:**
  - Every value carries `primary`.
  - None is in G01's macOS reserved table (⌘Q ⌘W ⌘H ⌥⌘H ⌘M ⌘Tab ⌘` ⌘C ⌘V ⌘X ⌘A ⌘Z ⇧⌘Z ⌘Space ⌃⌘F ⌘?).
  - None collides with the shell's Edit menu (⌘Z ⇧⌘Z ⌘X ⌘C ⌘V ⌘A) or Quit (⌘Q).
  - ⌘F, ⌘G and ⇧⌘G follow the macOS Find convention; ⌘R the reload convention; ⌘I the Get Info convention.

## Semantics and audit

- **No new handler shape.**
  - A Button shortcut dispatches through the button's own target and action (`ShortcutRouter.dispatch` → `NSControl.sendAction`). The server receives the same `ACTIVATE` as for a click, which G01 proves byte-identical (`ShortcutEventIdentityTests`).
  - Focus shortcuts send nothing.
  - `git diff ccc63f8f` adds no `session.on`. The PX-008 audit (`tests/no_process_control_test.rs`, unchanged) passes.
- **Disabled controls.** The router refuses a disabled node from the committed semantic state (`.disabled`), and the native control is disabled too. Event validation still refuses a forged event (`NodeDisabled`). The existing coverage is `sampling_test` (Refresh now while paused) and `search_test` (Next with no search).
- **Client-local interaction.** Focus, arrow-key selection, paging, scrolling and text selection never reach the server, except that a native selection change is reported as `SELECTION_CHANGED`, as for a click (PX-013).
- **Budgets.** Measured on the encoder (`cargo test … -- --nocapture`):
  - `PX-016 shortcuts: 14 bound, 288 bytes; filter=918/2048 search=2521/4096 owner=2466/4096 structure=1550/8192`.
  - Sampling 1159/2048, command line 8498/10240 and inspector 4548/6144, the last two unchanged from PX-015.
  - The row-less snapshot frame is 27346 bytes against 46339 bytes of allowances.

## Tests

- **Rust:**
  - `lib` `keyboard_shortcuts_are_canonical_unique_modified_and_on_admitted_controls` checks every value against the SDK's `Shortcut::parse`: canonical, `primary` set, at most `MAX_SHORTCUT_BYTES`, unique, one per node.
  - In both the uncollected shell and a collecting `FakeProcessSource` shell, exactly these nodes carry `SHORTCUT`, with these values, on node types that admit one. The Activate behavior is exactly the Buttons, and no Toggle is bound.
  - The store's own grammar, admission and uniqueness checks (G01) also run on the commit.
- **Native, over real SSH** with the unchanged generic client and `--fake-repeated-names` (60 rows, `worker` at rows 10, 30 and 50). Real key-down `NSEvent`s go through `window.performKeyEquivalent(with:)`. Typing, Delete, arrows and Page Up go through the first responder's own `keyDown(with:)`. The test host never activates, so `shortcutRouter.isWindowKey` is set for this window, as in G01's native tests. Every other guard is the real one. In order:
  1. **Discoverable and accessible.** For each of the fourteen bound controls:
     - the binding is present and canonical, with no diagnostic (no handle in the window has one);
     - the accessibility label is the published label;
     - the tooltip is `<label> (<shortcut>)`;
     - the accessibility help ends with `Keyboard shortcut <shortcut>` (also on the table's and the command line's inner views);
     - `isAccessibilityEnabled()` and `isEnabled` equal the published state: All visible users, Previous, Next and Restore are disabled, the rest enabled.

     A depth-first walk of `accessibilityChildren()` from the window's content view reaches them in the published reading order `[0 … 13]`.
  2. ⌘G with nothing searched: not dispatched, `.disabled`.
  3. **IME.** ⌘F focuses the search field (the field editor's delegate is the field). With marked text `かな`, ⌘R is not dispatched (`.markedText`) and the composition is untouched. The composition is then cancelled.
  4. **Reserved.** ⌘C in the field is not consumed by the window's key-equivalent path.
  5. **Typing.** "worker" is typed key by key, and each key is first offered as a key equivalent and refused. The server reports `"worker": 3 matches in 60 shown rows · match 1 of 3 at row 10 of 60` and the table selects row 10.
  6. **Stepping.** ⌘G, ⌘G, ⇧⌘G give selections `[9, 29, 49, 29]`.
  7. **Table.** ⌘L makes the table first responder, and an arrow key is refused as a key equivalent.
     - Down selects row 31, and the inspector shows that process.
     - Page Up scrolls the table locally and leaves the selection on row 31.
     - Up selects row 30, and the inspector shows `PID 5030 · worker`.
  8. **Inspect.** ⌘I makes the selectable, non-editable command-line text view first responder.
  9. **Sort.** ⌘2 gives `Sort by Name ↑` and the native rows equal the model's. ⌘1 gives `Sort by PID ↑` and the initial rows.
  10. **Filter.** ⌥⌘F focuses the filter field. Typing "worker" leaves 3 rows, all `worker`.
  11. **Reset.**
      - ⌘L, then ⌥⌘F, selects the whole filter (`NSRange(0, 6)`), and Delete brings back `showing all` and 60 rows.
      - ⌘F selects the whole query, and Delete gives `Search: none`. Rows and item IDs equal the initial ones.
      - ⌘G (Next, disabled again), ⌥⌘U and ⌥⌘R (nothing to reset) are each not dispatched, with `.disabled`.
  12. **Pause.** ⌥⌘P pauses: `Paused at …`, `Resume view`, Refresh now disabled and announced as disabled.
      - ⌘R is not dispatched (`.disabled`). The client revision is unchanged 600 ms later and the view is still paused.
      - ⌥⌘P resumes, and ⌘R is then dispatched.
  13. **Retained.** The table handle was built once and kept.
- **Mutation check.** Binding Refresh now to `primary+c` (reserved Cmd-C) still passes the Rust test, because the Rust side has no reserved table. The native test fails, reporting `.reserved(nodeID: NodeId(63), shortcut: "primary+c", …)`, no binding and no tooltip. The source was restored and rebuilt (`cmp` identical), and the native test passed again.

## Limitations

- **Key window.** The test host never becomes the active application, so the router's `isWindowKey` seam is set for the test window, as in G01. In a real session AppKit's key window applies.
- **Main menu.** The test drives `NSWindow.performKeyEquivalent`, not `NSApplication.sendEvent`, so the Edit menu's ⌘C/⌘A are not exercised end to end here. G01's `ApplicationMenuTests` covers the menu. This test shows only that ⌘C is not consumed by the application's shortcut path.
- **AX tree walk.** Reading order and the AX attributes are read in-process through `NSAccessibilityProtocol` on the real views. No out-of-process `AXUIElement` client (VoiceOver) was driven, because that needs the Accessibility (TCC) permission, which is not granted to the test host.
- **Horizontal scrolling and Home/End** are AppKit's own table behavior and were not separately exercised. Arrows and Page Up were.
- **Option-letter shortcuts on non-US layouts** match by the modifier-free character, per G01's matching rule. Only the US layout was run.
- **Buttons without shortcuts** (Only my processes, Go to PID, Apply interval, the column hide/move buttons) are reachable by Tab and Space only when Full Keyboard Access is on.
