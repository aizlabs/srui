## What was built

- **Registry (codegen contract).** Standard properties **32 `tree_depth`** and **33 `descendant_count`** (namespace 0, `uint64`, `control_specific`, model item properties) in `protocol/registry.yaml`; `PROPERTY_TREE_DEPTH = 32` and `PROPERTY_DESCENDANT_COUNT = 33` in `protocol/srui.proto`. `./protocol/generate_proto.sh` regenerated `srui.pb.swift` and `RegistryTables.swift`; `server-rust/semantic-tree/build.rs` asserts 33 properties; CLAUDE.md states 33. `spec/registries.md` §4.2/§4.4 document the shape, rules, codes, limit, disclosure, event arguments, columns, SDK and fallback. No new wire messages.
- **§26 limit.** `max_model_tree_depth`, default **256 levels** (`DEFAULT_MAX_MODEL_TREE_DEPTH`, Swift `defaultMaxModelTreeDepth`); a cached item's `tree_depth` must be **< 256** (deepest admitted depth 255). Rust `StoreLimits::with_max_model_tree_depth`, Swift `StoreLimits.withMaxModelTreeDepth` / `maxModelTreeDepth`.
- **Validation (Rust `Model::validate_tree_shape`, Swift `Model.validateTreeShape`, same order and codes).** Run after the **last operation of a transaction that touches the model** (`ModelTreeCheckpoints` in `transaction/apply.rs` and `SemanticStore.swift`), so a subtree edit plus its ancestors' `descendant_count` update is judged as one edit and a failure carries that operation's index. Applied on every path: authoritative commit, record, wire, delivered/coalesced, resync snapshot, `prepare_commit`, single `apply_operation`, Swift batch and single `apply`, and SDK `UiTransaction::check_model_trees` (run from `settle_promoted_selections`, so every SDK and sessiond commit path). Items in index order, cached items only, first violation wins:
  1. both values non-negative integers (absent = 0) — `invalid_model_tree_property`;
  2. `tree_depth < max_model_tree_depth` — `max_model_tree_depth_exceeded`;
  3. `index + descendant_count < item_count` — `model_tree_descendant_count_out_of_range`;
  4. index 0 is a root, and for cached neighbours `depth(i+1) <= depth(i) + 1` — `model_tree_depth_jump`;
  5. an item inside the nearest enclosing cached span is deeper than its owner and ends inside it, and a cached item directly after a span is no deeper than its owner — `model_tree_outside_parent_span`.

  A model that never held either property (sticky `tree_shaped` flag) is never checked, so flat models cost nothing. The check is O(cached items) per touched hierarchical model per transaction (Swift O(n log n) for sorted keys), marked `lc-debt` in both.
- **Event.** `Event::expansion_changed(seq, id, rev, node, item, expanded)` / Swift `Event.expansionChanged(…, itemId:, expanded:)` carry `value` = bool and `items` = `[ItemId]` (exactly one); Rust `Event::expansion_change()` reads it back and returns `None` for anything malformed.
- **SDK.** `TreeModel` / `TreeNode` flatten a forest iteratively into preorder items stamped with both properties, refuse a forest deeper than the limit (`TreeModelError::DepthLimitExceeded`) or with a duplicate `ItemId`, and build a `MODEL_RESET_RANGE` (`reset_op`); `TreeNode` drops iteratively so a 100 000-level forest cannot overflow the stack. `Tree` gains `columns` (builder/get/set/clear/op) and `Tree::on_expansion_changed(session, |ctx, ExpansionChange { node, item, expanded, observed_revision }|)`. `TREE_DEPTH`, `DESCENDANT_COUNT`, `ModelItem`, `StoreLimits`, `ModelTreeViolation`, `DEFAULT_MAX_MODEL_TREE_DEPTH` are re-exported.
- **AppKit client** (`Collections/OutlineCollectionAdapter.swift`, `CollectionRangeTracker.swift`, `RendererAppKit/ControlFactory.swift`, `CollectionSelectionPromotion.swift`):
  - flat `NSOutlineView` data source over the preorder; the outline-column cell (one reused `TreeCellView` per visible row) indents by cached `tree_depth` and shows a disclosure button for cached items with descendants; loading rows sit at level 0;
  - items start expanded; collapsing hides `index+1 … index+descendant_count`; the collapsed set is a `Set<ItemId>` of cached items only, pruned to cached items on every model update (index shifts follow the item; delete or eviction drops the entry) and kept across remounts by `ControlFactory.collectionDisclosureMemory`;
  - a sorted, merged hidden-interval list with prefix sums maps rows ↔ indices by binary search; uncached visible rows stay placeholders, and range requests are cut into the visible index runs with hidden intervals subtracted (`CollectionRangeTracker.requests(windows:)`; the single-window path is unchanged when nothing is collapsed);
  - collapse/expand sends no range request beyond uncached rows that become visible and emits `EXPANSION_CHANGED` once without awaiting a reply;
  - a revealing promotion expands only the collapsed items whose hidden intervals contain the promoted index (and reports each with `EXPANSION_CHANGED(expanded: true)`, so the server can know the client's disclosure state); a non-revealing restore never undoes a user's collapse;
  - `columns` reuses the Table column identifiers and cell projection (`CollectionCells`), first declared column as the outline column, header visible; a Tree without `columns` keeps one header-less outline column.
- **Interaction routing.** `SemanticInteraction.expansionChanged(nodeID:itemID:expanded:)` → `SessionController` → `SemanticAction.expansionChanged` (event type `EXPANSION_CHANGED`, admitted only where `standardEventsEmitted` lists it, i.e. Tree) → `EventOutbox.sendExpansionChanged`. The semantic inspector gained `setExpanded`.
- **Fallback.** A client without support renders the preorder flat with correct identity and selection (documented in the registry and `spec/registries.md`).

## Limitations

- Left/right arrow keys do not collapse or expand: native `NSOutlineView` expansion is unused (rows are a flat preorder). Pointer and the accessible disclosure button work.
- Collapsing a parent deselects a selected row inside it locally, without a `SELECTION_CHANGED`.
- A sparse replica cannot shift its cached indices for a `MODEL_DELETE` by `ItemId` of an item it does not cache (pre-existing §8 behaviour); hierarchical models should delete by index range, as documented in `spec/registries.md` and the SDK module docs.
- Validation is O(cached items) per touched hierarchical model per transaction; hidden intervals are rebuilt in O(k log k) per toggle or update (`lc-debt`).
- `StoreLimits` gained a public field, so an exhaustive struct literal without `..StoreLimits::default()` no longer compiles (one test updated).
- The fuzz table and its generator are not committed; the committed 315-row table and the Python reference keep the three implementations pinned.
