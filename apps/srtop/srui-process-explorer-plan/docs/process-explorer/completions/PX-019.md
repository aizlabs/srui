## What was built

- **Source model** (`src/source.rs`). `ProcessKey` gains `thread: Option<ThreadIdentity { tid, creation }>`; `ProcessRecord` gains `kind: Observed<TaskKind>` (`Process { threads }` with the kernel's thread count, `KernelThread`, `Thread`; `KIND_NOT_COLLECTED` for a source that cannot tell). Thread records live in `ProcessSnapshot::threads: ThreadScan` (`NotProvided` / `NotRequested` / `Read(ThreadRecords { records, unreadable, denied, capped, vanished })`), never in `records`, so nothing that counts processes can count a thread. `ProcessSource::collect_threads(on)` (default: ignored). `ProcessSnapshot::thread_retention` (`ThreadRetention`) names the processes whose threads were unreadable or capped; their earlier thread rows are kept only beside the process instance the scan confirmed, never by PID alone, and `ProcessSnapshot::retention` is unchanged (correction round 1). New deterministic fixture `ThreadsSource` (`--fake-threads`).
- **Linux reader** (`src/procfs.rs`). `stat` field 20 is parsed (`StatFields::threads`, unread never 0); a record's kind comes from `PF_KTHREAD` in field 9. While asked, after each non-kernel record the `task` directory is listed through the record's own pinned handle and each `task/<tid>/stat` is read: name, the thread's own CPU counters, start time. A thread gone between listing and read is churn; an unreadable listing or thread names the process once in `unreadable` (and `denied`); a listing gone with its process (exit confirmed by re-reading `stat`) names nothing. `MAX_THREAD_RECORDS` = 65,536 per scan (`with_thread_limit` lowers it): past it the process is named in `capped`. Per-thread CPU baselines are kept apart, keyed `(pid, process start, tid, thread start)`, rebuilt each scan, cleared when threads are hidden. `ProcFsSource::live()` reads no threads off Linux (`NotProvided`). `ProcFsDetails` reads a thread key's own state and start time from its task record and reports a reused TID as ended.
- **Projection** (`src/projection.rs`). Rows are each process followed by its threads. A snapshot is refused whole if a thread names a process it did not list, a process record names a thread, or a thread record names none.
- **Controls** (`src/lib.rs`, `src/refresh.rs`, `src/threads.rs`). Row 74 with **Show user threads** (75, off) and **Show kernel threads** (76, on) and the threads status (77), between the view switch and the collections; disabled with `Threads disabled: process collection not started` in the uncollected shell. Handlers: each toggle's `VALUE_CHANGED`, boolean only, value always republished (an exact pair added to the `no_process_control_test` allowlist). Showing user threads calls the sampling controls' existing `refresh_now` (one sample at once; none while paused); the refresh loop calls `collect_threads` before every sample. Hiding them republishes without thread rows and clears an inspector on a thread. Hiding kernel threads samples nothing. `THREADS_RESERVE_BYTES` = 4096 is charged in the row budget like every other control group.
- **Visibility and filters.** The toggles choose which rows the collection holds (`threads::admits`); the filters then choose processes, and a thread row is kept exactly when its process row is (`kept_with_processes`). The filter status counts rows; the user filter, the summary's match count and the process count count processes.
- **Table and sort.** After every sort, retention and eviction, `threads::group` puts each process's threads right after it, in their order among themselves; a thread whose process row is gone is dropped and counted as evicted.
- **Tree** (`src/tree.rs`). Threads never take part in PID resolution; a thread is placed under the process row its key names (whole-key match), as its first children, `Link::ThreadOf(P)` → Parent cell `thread of P`; `RootReason::ThreadProcessNotShown` otherwise. The depth limit applies as to any child. The view status counts `N processes and T threads under R roots`.
- **Inspector, follow, search.** A thread is named `TID t of PID p`; the inspector says `Selected thread: …` and `this thread has ended`. Go to PID never selects a thread row.

## Thread identity semantics

A thread's key is its process instance's whole key (source, host, boot, PID namespace, PID, process creation token) plus its TID and its own creation token — on Linux `task/<tid>/stat` field 22, read in the same read as its name and counters. Consequences: a thread that ends loses its row; a new thread gets a new item ID, also when the kernel reuses a TID inside the same process (different start time) or when a new process instance reuses the PID; every other row keeps its item ID; the tree attaches threads by that whole key, never by PID. The main thread is listed (TID = PID, start time = the process's). A TID the kernel reuses cannot be forced unprivileged (as for PIDs in PX-018), so TID reuse is exercised by the fixtures (`ThreadsSource` step 2, procfs tree `remove_thread`/`thread`) and the live test checks an ended-and-replaced thread.

## Counter policy

A **process row is the whole process**: its CPU share is `/proc/<pid>/stat` fields 14+15 — every thread, plus the time of threads that ended — and its resident memory is the process's. A **thread row is that thread alone**: its CPU share is `/proc/<pid>/task/<tid>/stat` fields 14+15; its Resident cell is `See process` (`Availability::Unsupported`), because a thread shares its process's address space and repeating the figure would count it once per thread. A process's thread rows split its CPU; adding a process row to its thread rows counts the time twice, and the threads status says so (`never add both`). srtop never adds rows: the summary's process count is `snapshot.records`, which never holds a thread; thread counts count each thread once (the kernel's `num_threads` while hidden, thread rows while shown). The catalogue's `CPU_USAGE`, `RESIDENT_MEMORY` and `PROCESS_ID` definitions state this.

## Bounds

- Thread records: at most `MAX_THREAD_RECORDS` per scan; at and past the bound the processes left short are named in `capped`, their earlier thread rows kept beside the same process instance only (see Correction round 1) (`the_thread_bound_names_the_processes_it_left_unread_at_and_past_the_bound`, limits 7, 6, 5, 4, 2, 1, 0 over six threads). Ledgers are bounded by the scan's `uncertain_limit`; a thread ledger past that bound (`ThreadRetention::Every`) keeps the earlier thread rows of every process instance this scan confirmed and says `thread listing incomplete`, never a process row and never the whole collection (`a_thread_ledger_past_its_bound_keeps_the_threads_of_every_confirmed_process`). Past the bound a process is still counted once, however many of its threads were unreadable (`a_process_with_several_unreadable_threads_is_counted_once_past_the_ledger_bound`).
- Rows: thread rows are rows under the same frame budget and `MAX_PUBLISHED_ROWS`; grouping puts a process before its threads, so the leading-rows ceiling never shows a thread without its process, and the tree keeps a preorder prefix (`the_row_ceiling_keeps_a_process_before_its_threads_at_and_past_the_bound`, limits 8, 7, 5, 4 over eight rows, with the status and filter-status counts).
- Scan cost: threads are read only while shown; then one `task` listing per user process and one bounded `stat` read per thread.

## Limitations

- **macOS and other non-Linux hosts** have no per-thread procfs: `--live-source` says user threads are unavailable (capability limitation). macOS live collection itself remains unsupported, as before.
- **A thread's owner is its process's.** Per-thread credentials that differ (a raw `setresuid` on one thread) are not read; the user filter chooses processes anyway.
- **Per-thread memory is not shown** (`See process`). Advanced per-thread metrics (state column, last CPU, NLWP column) are PX-043.
- **TID reuse** is not forced live (needs `CAP_SYS_ADMIN`/`CAP_CHECKPOINT_RESTORE`); fixtures cover it.
- **Which processes the thread bound leaves unread** follows the root's directory order, like the record bound; what is read and what is named are exact.
- **No keyboard shortcut** for the two checkboxes; PX-016's shortcut table is unchanged.
- **Pause.** Showing user threads while paused reads nothing until Resume view, and the status says so.
- Independent verification is pending.

## Correction round 1

Independent verification failed `4ef06ca8` on one blocking finding (F1) and three non-blocking ones (F2–F4).

- **F1 (blocking): a dead instance stayed published beside the process that reused its PID.** Root cause: `ProcessSnapshot::retention` added the PIDs of the thread ledgers (`ThreadRecords::unreadable`, `::capped`) to the PID-keyed record `Retention`, and `retain_unconfirmed` then kept *every* absent row with such a PID — process rows as well as thread rows, of any instance. When a PID was reused and the new instance's threads were unreadable or past the thread bound, the ended instance's process row and threads stayed next to the successor on every such scan (summary `5 listed` against `showing all 6 processes`). Fix: the thread ledgers no longer feed `Retention`. They form a separate `ThreadRetention` (`None` / `Named(pids)` / `Every`, from `ProcessSnapshot::thread_retention`), and `apply` keeps an absent row on its account only when the row is a **thread** whose PID it covers **and** whose process key (whole key, anchored) is a process row this scan confirmed. A process row is never kept by it; a thread of an earlier instance never is. A thread ledger that could not name everything no longer makes the whole scan `Unenumerable`: it keeps the absent threads of the processes this scan confirmed, never more. Audit of the other PID-keyed uses: the record `Retention` names PIDs whose *records* went unread, so no instance with that PID was confirmed in the same scan and no successor can stand beside the kept row (unchanged PX-004 rule, which errs towards keeping); `Retention::Unenumerable` keeps everything by design (PX-004), and the threads it keeps are attached to their own instance by key (`threads_stay_with_their_own_instance_when_two_instances_share_a_pid`); `ScanGaps` only words Parent cells; Go to PID ignores thread rows. Code: `src/source.rs` (`retention`, `thread_retention`, `ThreadRetention`), `src/refresh.rs` (`apply`, `retain_unconfirmed_by`).
- **F2: test gaps.** New tests kill each named mutant: M2a (tree attaches a thread by PID) and M2d (`kept_with_processes` by PID) and M3a (status line counts threads as listed) by `threads_stay_with_their_own_instance_when_two_instances_share_a_pid` (two instances of PID 100 in one generation, kept by an unenumerable scan: each instance's threads follow it in the table, sit under it in the tree, follow it through a filter, and the status says `2 processes listed`); M8 (thread rows kept after a scan that read no threads) by `a_scan_that_read_no_threads_keeps_no_thread_row_even_of_a_kept_process`.
- **F3:** `pause_view` and `resume_view` now republish the threads status in their commit (`publish_sampling`), so Resume view no longer leaves "the view is paused: Resume view reads them" on screen (`resuming_republishes_the_threads_status`).
- **F4:** follow on a thread stopped by hiding user threads says `… is no longer shown: user threads are hidden; show them, select a row and turn follow on again` (`follow_on_a_thread_says_user_threads_were_hidden`).

Regression tests for F1: `a_reused_pid_whose_new_threads_are_unreadable_keeps_no_row_of_the_ended_instance` and `a_reused_pid_past_the_thread_bound_keeps_no_row_of_the_ended_instance_over_scans` (three capped scans; the same-instance `init` thread row keeps its item ID throughout).
