## Design decisions

### 1. What "watched" means

Three things the user chose, and nothing else: **the inspector's target** (PX-013), **the followed process** (PX-017; normally the same instance, but follow stays on its process when a collapse clears the inspector), and **a tagged process** (PX-020). One store, `LastSeen` (`src/lastseen.rs`), holds a tombstone for each watched instance that leaves the server-side collection. It replaces PX-020's separate historical-tag list: a historical tag *is* a tagged tombstone, so the tags status, the follow status and the inspector use one verdict and one vocabulary. PX-013's "this process has ended" (said for any row that left, including evicted ones) and PX-020's "no longer listed" are both replaced by `exited` or `no longer observed`, as established below; PX-017's "has ended" in the follow status likewise.

### 2. What establishes an exit

On Linux `/proc/<pid>` exists from creation until the task is reaped; a zombie keeps its directory and is listed with state `Z` (`proc(5)`, `proc_pid_stat(5)`). A process that exists for the whole of a `getdents` over `/proc` is listed by it. So an instance **exited** (and was reaped) when:

- `Exit::Unlisted` — a scan whose retention is `Retention::Skipped` and does not name the PID (it read the list and accounted for every entry it did not publish: denied, unreadable and capped records are named), and whose records carry the *same known* source, host, boot and PID namespace as the instance, no longer lists the PID. A record that vanished between listing and reading (`ENOENT`/`ESRCH`, `ProcessSnapshot::vanished`) is the same absence.
- `Exit::Replaced` — the same scan lists the PID with another creation token (field 22): a PID is only reused after its holder is gone.
- `Exit::DetailRead` — the inspector's detail read found the record gone or its start time different (`DetailRead::Ended`, PX-013); this upgrades a departure the scan could not establish.
- Threads: `Exit::Unlisted`/`Replaced` when the thread's process instance was confirmed, the sample read threads, the thread ledgers do not name the process (`ThreadRetention`), and its `task` listing no longer lists the TID or lists it under another start time; `Exit::WithProcess` when its process exited.

Everything else is **no longer observed** ("…; whether it exited is unknown"):

- `Unobserved::Evicted` — the row was kept because scans could not account for it (`Retention::Unenumerable`: unreadable root, unexaminable entry, ledger overflow; or `Retention::Skipped` naming its PID: a denied/unreadable `/proc/<pid>` or a capped record), and then the row ceiling dropped it (`evict_unconfirmed_beyond`).
- `Unobserved::IdentityUnconfirmed` — the scan's host, boot or PID namespace is unknown or differs, or it listed no records at all, so its listing says nothing about this instance. (The session identity anchor, PX-003, still keeps every *listed* instance on its key, so an unreadable identity file never churns rows; it only stops absences from proving exits.)
- `Unobserved::ThreadsNotRead` / `WithProcess` for threads.

A scan that could not list the processes, or that this app rejected, takes the status-only path and keeps every row: nothing leaves, so nothing is recorded. **ScanGaps** (PX-018) only explain absent parents and take no part. **Fixture and synthetic sources** state their own completeness and identity; their absences are exits by their own statement under the same rule, and a source that cannot account for absences reports itself unenumerable and never produces an exit. srtop has no non-Linux live collector (`--live-source` on macOS is a collector error).

Nothing else is claimed: no exit status, no cause, no signal and no history between samples.

### 3. Where it is shown

The **inspector** (its existing five lines): `Selected process: PID 300 · worker · exited: a scan that accounts for its PID no longer lists it · last observed 2027-01-15 08:00:00 UTC; a historical record: no action applies to it`; `Name: … · Owner: …`; `Last read · State: … · Parent: … · Started: …` (or `none read while it was observed`); `Last sampled · CPU: … · Resident: … · last observed …`; `Command line: not kept once the process left the list: arguments can carry secrets`. The command line, executable and working directory are deliberately not kept: PX-014 shows arguments only for a listed process (`live::live_secret_argument_body` asserts an ended target's secret argument is no longer shown), and a tombstone must not extend that exposure. A thread says `Selected thread: TID 201 of PID 200 · worker-1 · exited: a scan that read its process's threads no longer lists it · …`. Once the record is no longer kept: `… its last-observed record is no longer kept (records are kept at most 10 minutes, 64 records and 32 KiB, the oldest dropped first); select another row` (correction round 1: the bound that dropped it is not known, so all three are named). The **follow status** (`Follow stopped: PID 6010 · tracked exited · …` / `… is no longer observed · …`) and the **tags status** (`1 historical: PID 300 · make exited, last observed …`, three newest named, `(N forgotten)`) carry the same verdict. No historical row is added to the list (a row would be counted, sorted, filtered and summarized as a process). Existing generic widgets only.

"Disable all process actions": srtop has no process-changing action (the no-process-control audit is unchanged and passes). The only requests that take the selection as a target refuse a tombstone: `Nothing tagged: PID 300 · worker exited: a historical record is never tagged`, `Follow: off · PID 300 · worker exited: a historical record is never followed; select a listed process first`.

### 4. Clock and bounds

`ProcessView` ages tombstones by an injected `procfs::MonotonicClock` (default `SystemMonotonicClock`; `ProcessView::with_clock` for tests). Times shown are the scans' own `sampled_at` (server wall clock, UTC to the second): `last_observed` is the last scan that *listed* the row, carried across scans that only kept it (`unconfirmed_since`, bounded by and replaced with `unconfirmed`), so a row kept by an unenumerable scan is not reported as observed by it.

### 5. Interactions

- **Tree and collapsed mirror.** A departed target in the tree shows the same tombstone; `prune_collapsed` drops its item as before (`the_tree_shows_the_same_tombstone`).
- **Threads.** A selected (or followed) thread gets a tombstone with its own verdict (`a_selected_thread_gets_a_tombstone_and_a_hidden_one_does_not`; `threads_test::the_inspector_and_follow_name_a_thread_and_see_it_end`). Hiding user threads clears an inspector on a thread first (PX-019), so the sample that drops thread rows records nothing for it. Tags never mark threads (PX-020).
- **Tags.** Historical tags are tagged tombstones: `Tags::retire` only takes keys off the live set; `LastSeen` is held and restored with the set on a failed tag request; a sample whose tags status did not commit puts the live tag back and untags its tombstone, and the next committed sample re-tags it.
- **Follow.** Stops with the verdict when its process leaves; refuses a tombstone.
- **Pause.** Nothing recorded or expired while frozen; the first sample after Resume records the exit with the pre-pause last-observed time (`a_paused_view_records_nothing_until_it_resumes`).
- **Filters.** A filter never creates a tombstone; a filtered-out target that leaves gets one (`a_filtered_out_target_is_not_historical_until_it_leaves`).
- **Failed commits** (`commit_fault`). A tombstone is server knowledge, recorded when the sample is applied whatever its commits do; the next publication shows it (`a_failed_sample_records_the_tombstone_and_the_next_publication_shows_it`). A failed Clear tags keeps the historical tags (`a_failed_clear_keeps_the_historical_tags`). PX-020's `a_failed_sample_keeps_an_ended_process_tagged_until_one_commits` still holds.
- **No-process-control audit.** No handler, event or source call added; `tests/no_process_control_test.rs` passes unchanged.

Now every historical tag is counted once: `1 historical, forgotten` / `N historical, all forgotten` when none is left to name, and otherwise `N historical: A; B; C and K more (F forgotten)`, where `K` = `N` − named and the forgotten ones are part of `K`. Tested at 0, 1, 3 and 5 named and after age, count and byte expiry (`lastseen::tests::the_tags_status_counts_every_historical_tag_once`) and through the view (`an_aged_out_historical_tag_is_counted_once_even_on_an_unreadable_scan`).
- **F2, a stale record after the instance was listed again** (`src/lastseen.rs`). `LastSeen::record` kept the first record of an instance forever, so an instance evicted (`no longer observed`), listed again and then really exiting still showed the old verdict, the old last-observed time and stale cells. Now (a) a scan that lists an instance again drops its record when that record only said `no longer observed` (`LastSeen::drop_relisted`, before departures are recorded; a historical tag dropped so is neither forgotten nor put back on a row); the inspector, still on the old row, says `listed again after it was no longer observed, under a new row; select that row to inspect it`; and (b) a later departure replaces any earlier record with its own sample, time and verdict, as the newest entry. An `exited` record stays while an instance with the same key is listed: the kernel never reuses a (PID, start time) pair within a boot, so only a source that reuses its own tokens (the `--fake-sequence` script's cycle) does that. "Last observed" is therefore always the last scan that listed the instance. ## Limitations

- **A verdict is not upgraded in place.** A later scan that accounts for an evicted instance's PID does not turn its `no longer observed` into `exited`; if a later scan lists it again, the record is dropped instead (correction round 1), and a later departure records afresh.
- **`hidepid=invisible` remounted mid-session** would make other users' processes vanish from a listing that still reports itself complete; procfs gives the scan no way to tell, so their absence would read as an exit. A mount option change is outside what one scan can observe.
- **Unreadable identity is conservative.** While the host, boot or PID-namespace identity cannot be read, no absence is an exit (`no longer observed`), even though the session anchor keeps listed instances on their keys.
- **Only watched instances get records**, and only the inspector shows a whole record; the tags status names the three newest historical tags with their verdict and last-observed time.
- **Expiry is evaluated at accepted samples** (readable or not), so a paused view keeps its records past their age until resumed.
- The `inspector_test::the_inspector_stays_on_its_process…` name-cache flake (pre-existing); see Verification.
- Independent verification is pending.
