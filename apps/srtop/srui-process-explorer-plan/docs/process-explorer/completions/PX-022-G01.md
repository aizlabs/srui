## Design reading

- D1 §17: losing the network moves a session to DETACHED while the application lives on. The client still shows its replica, but that data is no longer live, so the window says it is stale. Only the client knows its transport is gone. A server cannot report that the socket is alive, so this status is client chrome.
- D1 §18: the server decides continuity, and the client waits for that decision. A REPLACED decision discards the old replica, so the window says the session is rebuilding, with no revision to call stale. "Resume attempts are generation-bound": a superseded attempt's outcome must not change what the window says.
- D1 §22.3: a Surface maps to an `NSWindow` held by its render handle. A remount closes the windows and builds new ones, so a status stored on a window would be lost. The renderer keeps it.
- D1 §22.8: the status must reach VoiceOver through native accessibility.
- D1 §18.3 and D2 T29: pending text edits are untouched.
- D2 T22–T24 (attach/detach, journal replay, event settlement) are unchanged; this ticket only shows their outcome. D2 T38 (the connection manager) owns `ConnectionStatus`, which now also drives the window chrome.

## Implementation

### `client-macos/RendererAppKit/LayoutRenderer.swift`, `AppKitRenderer.swift`

- `AppKitRenderer.setSessionWindowStatus(_:)` and `sessionWindowStatus` forward to `LayoutRenderer`. `LayoutRenderer` holds `sessionWindowStatus: String?`, where `nil` or an empty string means no status. Setting it writes every Surface window at once.
- `mount(nodeID:from:)` applies the stored status to each Surface window it creates. Every Surface window, whether from the first mount, a structural-commit remount, `attach(store:)` or a later Surface, gets it.
- **Why `NSWindow.subtitle`.** AppKit draws it in the title bar under or beside the title (macOS 11+). The client already targets macOS 14+. No Surface property writes it. The server's `label` keeps writing `NSWindow.title` (`ControlFactory.swift:403`, unchanged), so neither overwrites the other. Other options were rejected:
  - a title suffix would fight the server title;
  - a banner view inside the content would join the server-laid-out hierarchy and its key-view loop;
  - a title-bar accessory view needs more AppKit surface for the same result.
- **Accessibility.** On this macOS (26.4.1), AppKit already folds the subtitle into the window's accessibility title: `accessibilityTitle` is `Server Title – disconnected — showing data from revision 7 (stale)` (native evidence below). That behaviour is not documented for every release, and CI runs `macos-15`. So the window's accessibility help (`setAccessibilityHelp`) also carries the same text. Nothing else writes it: the server's `accessible_description` sets the help of the Surface's content view, not of the window. It is cleared together with the subtitle.

### `client-macos/ConnectionManager/ConnectionManager.swift`

- `ConnectionStatus.sessionWindowStatus(lastAppliedRevision:)` maps each status to its chrome:
  - `unknown` and `connected`: `nil`.
  - `connecting`: `connecting — showing data from revision N (stale)`.
  - `resynchronizing`: `resynchronizing — showing data from revision N (stale)`.
  - `disconnected(resumeAvailable:)`, either value: `disconnected — showing data from revision N (stale)`.
- `ConnectionStatus.sessionReplacedWindowStatus` is `session replaced — rebuilding`. N is the context applier's `lastAppliedRevision`, the replica the window shows.
- `setStatus(_:for:replaced:)` is now the only writer of `statuses[...]` outside `load()` and the new-draft `.unknown`, which have no context yet. It writes the status and the chrome on the context's renderer together. Callers:
  - `beginAttempt`: connecting;
  - `handle`: connecting, resynchronizing, REPLACED (`replaced: true`) and ready;
  - `markDisconnected`;
  - `shutdown`.
- **Generation.** Each caller already sits behind the `activeTokens[connectionID] == token` checks that guard `ConnectionStatus`. A superseded attempt's late outcome therefore reaches neither the status nor the chrome, and no second guard was added. Mutant M4 removes the guards in `recordFailure` and `markDisconnected`, and the new superseded-attempt test then fails.
- **Closer.** `discardContext(for:)` clears the renderer's status before it removes a context. It runs in three places:
  - a failed first connection (`markDisconnected`, pending);
  - `remove(id:)` with no active attempt, and the end of an attempt whose entry was removed (`runAttempt`);
  - drafts that never connected, at `shutdown`.
- Lifetime: the status lives on the renderer and is overwritten at the next status change. A ready status clears it. A window that closes takes its subtitle with it, and the renderer's next window gets the current status.

## Tests

`client-macos/Tests/RendererAppKitTests/SessionWindowStatusTests.swift` (swift-testing, new suite `Session window status (PX-022-G01; §17, §18, §22.8)`):

1. *setting, changing and clearing the status updates every Surface window*. Two Surfaces. Set, change, clear with `nil`, and clear with `""` update every window's subtitle and accessibility help.
2. *the server title and the client status never overwrite each other*. The title stays `Server Title` when the status is set. A `label` set-property commit, applied in place to the same window, renames the title and keeps the status. Clearing the label gives `SRUI` and keeps the status. Clearing the status leaves the title alone.
3. *a status set before the first mount reaches the first windows*.
4. *a window a later commit creates, and every window a remount rebuilds, keep the status*. A structural commit adds a Surface: the rebuilt window is a new `NSWindow`, and both windows carry the status. A full `attach(store:)` remount keeps it. Clearing reaches the rebuilt windows, and a later remount stays clear.
5. *a real NSWindow shows the status beside the server title*. After `showWindows()` (concealed in the test host, `isVisible`), the window has its title, subtitle and accessibility help. The test writes the native evidence line.

`client-macos/Tests/SRUITests/ConnectionManagerTests.swift` (swift-testing, existing suite). The tests use fake attempts. Revision 1, with a titled Surface, is committed to the context's applier and mounted on its renderer, so the chrome is read off a real `NSWindow`. Every wait is `AsyncTestSupport.observed` on the observable status or alert. The two waits on non-observable state use the existing `.roundTrip` helpers, as the neighbouring tests do.

6. *every connection status maps to its session-window chrome*: the pure mapping, for every case.
7. *session windows follow every connection status transition*:
   - connecting at revision 0, which reaches a window mounted afterwards;
   - ready clears it;
   - `.stopped` gives disconnected at revision 1;
   - a reconnect on the same context gives connecting at revision 1;
   - resynchronizing at revision 1;
   - ready clears it again;
   - shutdown gives disconnected at revision 1.

   The title stays `Server Title` throughout, and the accessibility help follows the status.
8. *REPLACED says the session is rebuilding until ready clears it*: a window mounted during the decision shows `session replaced — rebuilding`, and ready clears it.
9. *a superseded attempt's late failure cannot overwrite the newer window status*. The first attempt's gated start fails after a second attempt has reached resynchronizing. The window keeps `resynchronizing — … revision 1 (stale)`, and ready then clears it.
10. *a session context is dropped only after its window status is cleared*. Two cases: a failed first connection, and removing a disconnected entry.

## Limitations

- Status changes are not spoken. VoiceOver reads the status with the window (accessibility title on macOS 26, accessibility help everywhere), but nothing posts an announcement when the status changes. Out of scope.
- During a reconnect and catch-up, "revision N" is the applier's last applied revision. While a commit is published but not yet rendered (PX-018-G02's gap), it can be one revision ahead of what the window draws. The transport is not live in those states, so no further commit lands while the label stands.
- After REPLACED, the replica is reset. A disconnect before the replacement snapshot is ready reads `disconnected — showing data from revision 0 (stale)`.
- Accessibility on `macos-15` (CI) is covered by the asserted accessibility help. Whether that release also folds the subtitle into the accessibility title was not observed locally.
- PX-022 itself, which will use this in srtop's flows (detached cached inspection, disabled process actions, replay and replacement semantics), is still to do.
