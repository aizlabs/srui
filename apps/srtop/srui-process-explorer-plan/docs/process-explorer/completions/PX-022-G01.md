## Design reading

- D1 §17: losing the network moves a session to DETACHED while the application lives on. The client still shows its replica, but that data is no longer live, so the window says it is stale. Only the client knows its transport is gone. A server cannot report that the socket is alive, so this status is client chrome.
- D1 §18: the server decides continuity, and the client waits for that decision. A REPLACED decision discards the old replica, so the window says the session is rebuilding, with no revision to call stale. "Resume attempts are generation-bound": a superseded attempt's outcome must not change what the window says.
- D1 §22.3: a Surface maps to an `NSWindow` held by its render handle. A remount closes the windows and builds new ones, so a status stored on a window would be lost. The renderer keeps it.
- D1 §22.8: the status must reach VoiceOver through native accessibility.
- D1 §18.3 and D2 T29: pending text edits are untouched.
- D2 T22–T24 (attach/detach, journal replay, event settlement) are unchanged; this ticket only shows their outcome. D2 T38 (the connection manager) owns `ConnectionStatus`, which now also drives the window chrome.

## Implementation

### `client-macos/RendererAppKit/LayoutRenderer.swift`, `AppKitRenderer.swift`

- `AppKitRenderer.setSessionWindowStatus(_:)` and `sessionWindowStatus` forward to `LayoutRenderer`. `LayoutRenderer` holds `sessionWindowStatus: String?`, where `nil` or an empty string means no status. Setting it writes every Surface window at once.
- `mount(nodeID:from:)` applies the stored status to each Surface window it creates. Every Surface window, whether from the first mount, a structural-commit remount, `attach(store:)` or a later Surface, gets it.
- **Why `NSWindow.subtitle`.** AppKit draws it in the title bar under or beside the title (macOS 11+). The client already targets macOS 14+. No Surface property writes it. The server's `label` keeps writing `NSWindow.title` (`ControlFactory.swift:403`, unchanged), so neither overwrites the other. Other options were rejected:
  - a title suffix would fight the server title;
  - a banner view inside the content would join the server-laid-out hierarchy and its key-view loop;
  - a title-bar accessory view needs more AppKit surface for the same result.
- **Accessibility.** On this macOS (26.4.1), AppKit already folds the subtitle into the window's accessibility title: `accessibilityTitle` is `Server Title – disconnected — showing data from revision 7 (stale)` (native evidence below). That behaviour is not documented for every release, and CI runs `macos-15`. So the window's accessibility help (`setAccessibilityHelp`) also carries the same text. Nothing else writes it: the server's `accessible_description` sets the help of the Surface's content view, not of the window. It is cleared together with the subtitle.

### `client-macos/ConnectionManager/ConnectionManager.swift`

- `ConnectionStatus.sessionWindowStatus(lastAppliedRevision:)` maps each status to its chrome:
  - `unknown` and `connected`: `nil`.
  - `connecting`: `connecting — showing data from revision N (stale)`.
  - `resynchronizing`: `resynchronizing — showing data from revision N (stale)`.
  - `disconnected(resumeAvailable:)`, either value: `disconnected — showing data from revision N (stale)`.
- `ConnectionStatus.sessionReplacedWindowStatus` is `session replaced — rebuilding`.
- N is the context applier's `lastAppliedRevision`, read once when the transition happens. It is not the revision the window draws (verification round 1, F2):
  - it can lead by one, when a commit is published but its render is superseded by the disconnect;
  - it can trail, when a snapshot or replay mounts while connecting or resynchronizing, until the next transition rewrites the line.

  Either way the line says `(stale)` in every non-live state, so live data is never claimed (D2 T29: no stale content shown as current). Taking N from the rendered revision would need the renderer to format the line on every render, which this ticket does not do.
- `setStatus(_:for:replaced:)` is now the only writer of `statuses[...]` outside `load()` and the new-draft `.unknown`, which have no context yet. It writes the status and the chrome on the context's renderer together. Callers:
  - `beginAttempt`: connecting;
  - `handle`: connecting, resynchronizing, REPLACED (`replaced: true`) and ready;
  - `markDisconnected`;
  - `shutdown`.
- **Generation.** Each caller already sits behind the `activeTokens[connectionID] == token` checks that guard `ConnectionStatus`. A superseded attempt's late outcome therefore reaches neither the status nor the chrome, and no second guard was added. Mutant M4 removes the guards in `recordFailure` and `markDisconnected`, and the new superseded-attempt test then fails.
- **Closer: no window outlives its attempt without its status.** This was fixed after verification rounds 1 (F1), 2 (V2-F1), 3 (V3-F1, V3-F2) and 4 (V4-F1).
  - `discardContext(for:)` removes the context from `contexts` and at once calls `closeWindows(of:)`. That clears the status and mounts an empty store, so `LayoutRenderer.tearDown` closes every Surface window, as the REPLACED reset in `SessionController.resetSharedStateForReplacement` does. It does nothing when the registry is already empty.
  - Each `runAttempt` also knows its request's context. After `await attempt.stop()` it calls `closeWindows(of:)` again whenever the manager no longer owns that context (`contexts[id] !== context`). This second close catches a render that was already in flight when the session failed and reopened a window after the first close.
  - `SessionControllerConnectionAttempt.stop()` is shared: the first caller starts one stop `Task`, and every caller awaits that same task. So the tail's `await attempt.stop()` returns only once the controller has finished stopping, including `deactivateReferenceOwner`, even when `shutdown()` began the stop first. Before, `SessionController.stop()` returned at once while another stop was running.
  - Earlier rounds, each found by the verifier:
    - Round 1 only cleared the status. AppKit keeps a shown `NSWindow` alive after its renderer is released, and nothing else closes it. The verifier's probe showed the window still visible and in `NSApp.windows`, with an empty subtitle: a frozen window that read as live.
    - Round 2 closed immediately, inside `handle(.failed)`, and never again. A render already in flight then mounted the snapshot and showed a window nobody closed (probe F).
    - Round 3 deferred the close to the tail. A visible window then sat with an empty subtitle until the failure's save and stop finished, 3–16 ms normally and unbounded if the save stalled (V3-F2).
    - Round 3's tail could also return from `stop()` before the controller had stopped when `shutdown()` stopped the attempt first, so a paused render could still show a window after the close (V3-F1, probe S).
    - Round 4 did not discard when a removed entry's session ended. `handle()` returned on `.failed` or `.stopped` for a missing entry without touching the window, and `markDisconnected` returned early for one. A live window with no status therefore stayed up until the stop finished: 6–12 ms normally, and indefinitely with the stop paused (V4-F1, probe P1). A connection that was not deleted shows `disconnected — … (stale)` at once.
- **Why the shared stop lives in the attempt rather than in `shutdown`.** Every stop in the manager goes through `SessionControllerConnectionAttempt.stop()`: the tail, `shutdown()`, and `beginAttempt`'s fallback. Making that one method await a single stop gives every caller the same guarantee without touching `SessionController`. A `shutdown`-only sweep would leave any future concurrent stop exposed.
- **Why close rather than leave a terminal `disconnected — …` line.** A dropped context is never reconnected or reopened:
  - `connect` mints a fresh context;
  - `open` needs the context;
  - removing an entry only forgets it locally (D2 T38), while the remote session lives on (§17).

  A window left behind could therefore never become live again or be reached from the Connections window. Pending text in it belongs to the dropped outbox and would never be sent either (§18.3 applies to resume only).
- `discardContext` runs as soon as nothing can bring the session back for that entry, and every call closes the windows at once:
  - a failed first connection (`markDisconnected`, pending);
  - the end of a removed entry's session, on its `.failed` or `.stopped` in `handle()`, or on any failure reaching `markDisconnected` for a missing entry (round 5);
  - `remove(id:)` with no active attempt;
  - the end of an attempt whose entry was removed (`runAttempt` tail, a no-op by then);
  - drafts that never connected, at `shutdown`.

  A context still owned is never closed: a reconnect reuses it.
- Test seam: `ConnectionManager.makeSessionControllerAttempt(request:transport:configureController:)` takes an optional closure (internal, default `nil`), so a test can install `SessionController` interceptors.
- **A removed entry whose attempt is still running** (F3). `remove(id:)` still does not stop the session (existing behaviour: "deleting a row is local bookkeeping"), and its windows stay open. `handle()` used to skip the chrome for a missing entry, so after `.ready` the windows kept `connecting — … (stale)`. It now calls `showWindowStatus` for connecting, resynchronizing, REPLACED and ready. When that session's transport ends, its windows close at once. A deleted row will never be reconnected, so closing fits better than a stale line that could never be cleared. The `runAttempt` tail closes them again after the stop.
- **Audit of the other `handle()` branches for a removed or superseded entry (round 5).**
  - A removed entry's connecting, resynchronizing, REPLACED and ready events update its windows (F3), so a window is never without its status while the session is not live.
  - A superseded attempt's events stop at the token guard. Its context is either the newer attempt's, which then owns the chrome, or a dropped draft context, which was closed at discard and is closed again in its own tail.
  - Failures outside `handle()`, such as a start error or the stream ending without `.stopped`, reach `markDisconnected` through `recordFailure` or `recordStopped`, which now also discards a missing entry.
- Lifetime: the status lives on the renderer and is overwritten at the next status change. A ready status clears it. A window the user closes takes its subtitle with it, and the renderer's next window gets the current status.

## Tests

`client-macos/Tests/RendererAppKitTests/SessionWindowStatusTests.swift` (swift-testing, new suite `Session window status (PX-022-G01; §17, §18, §22.8)`):

1. *setting, changing and clearing the status updates every Surface window*. Two Surfaces. Set, change, clear with `nil`, and clear with `""` update every window's subtitle and accessibility help.
2. *the server title and the client status never overwrite each other*. The title stays `Server Title` when the status is set. A `label` set-property commit, applied in place to the same window, renames the title and keeps the status. Clearing the label gives `SRUI` and keeps the status. Clearing the status leaves the title alone.
3. *a status set before the first mount reaches the first windows*.
4. *a window a later commit creates, and every window a remount rebuilds, keep the status*. A structural commit adds a Surface: the rebuilt window is a new `NSWindow`, and both windows carry the status. A full `attach(store:)` remount keeps it. Clearing reaches the rebuilt windows, and a later remount stays clear.
5. *a real NSWindow shows the status beside the server title*. After `showWindows()` (concealed in the test host, `isVisible`), the window has its title, subtitle and accessibility help. The test writes the native evidence line.

`client-macos/Tests/SRUITests/ConnectionManagerTests.swift` (swift-testing, existing suite). The tests use fake attempts. Revision 1, with a titled Surface, is committed to the context's applier and mounted on its renderer, so the chrome is read off a real `NSWindow`. Every wait is `AsyncTestSupport.observed` on the observable status or alert. The two waits on non-observable state use the existing `.roundTrip` helpers, as the neighbouring tests do.

6. *every connection status maps to its session-window chrome*: the pure mapping, for every case.
7. *session windows follow every connection status transition*:
   - connecting at revision 0, which reaches a window mounted afterwards;
   - ready clears it;
   - `.stopped` gives disconnected at revision 1;
   - a reconnect on the same context gives connecting at revision 1;
   - resynchronizing at revision 1;
   - ready clears it again;
   - shutdown gives disconnected at revision 1.

   The title stays `Server Title` throughout, and the accessibility help follows the status.
8. *REPLACED says the session is rebuilding until ready clears it*: a window mounted during the decision shows `session replaced — rebuilding`, and ready clears it.
9. *a superseded attempt's late failure cannot overwrite the newer window status*. The first attempt's gated start fails after a second attempt has reached resynchronizing. The window keeps `resynchronizing — … revision 1 (stale)`, and ready then clears it.
10. *a failed first connection closes the windows it had mounted*. The failure’s save is held, so the attempt is still running. The shown window is already closed: not visible, no visible window left in `NSApp.windows`, registry empty, status `nil`. It stays closed after the attempt stops. With round 3’s deferral restored (mutant N30), this test fails.
11. *removing a disconnected entry closes its windows*. Before removal, the shown window says `disconnected — … revision 1 (stale)`. After `remove(id:)` it is closed.
12. *a removed entry's running session keeps its window status, then closes when it ends*. Steps:
    - remove the entry while connecting; the window stays open with `connecting … revision 0`;
    - `.connecting` gives `connecting … revision 1`;
    - REPLACED gives `session replaced — rebuilding`, with no alert;
    - `.resynchronizing` gives `resynchronizing … revision 1`;
    - `.ready` clears the status, and the window stays open;
    - `.stopped` closes the window.
13. *a render in flight when a first connection fails cannot leave a window open* (round 2, modelled on verifier probe F). Setup:
    - a real `SessionController` over `ConnectionManagerCaptureTransport`;
    - `rendererResourcesPreloadedInterceptorForTesting` installed through `makeSessionControllerAttempt(…, configureController:)`;
    - a `SavedConnectionStore(url:beforeSave:)` gate.

    Steps:
    - WELCOME and a snapshot arrive, and the render pauses before it mounts;
    - `transport.fail()`, and the draft is removed while the attempt is still active;
    - the render is released; it mounts and shows a window after the context was dropped;
    - the save is released, and the attempt stops;
    - the window is then closed and the registry is empty.

    With no close in the tail (mutant M12), this test fails.
14. *a render that lands while the failed attempt is stopping is closed after the stop* (round 3, V3-A1, modelled on probe R). The failed attempt’s own stop pauses on `stopWillRetireMountForTesting`, and the paused snapshot render is released. The render lands during the stop and shows a window. After the stop, the window is closed and the registry is empty. With the tail close moved before `stop()` (mutant N26), this test fails.
15. *shutdown's stop and the failed attempt's own stop share one stop before the close* (round 3, V3-F1, modelled on probe S). Steps:
    - the failure's save is held;
    - `shutdown()` starts, and its stop pauses before retiring the mount;
    - the save is released, and the attempt's tail reaches `stop()`;
    - the tail must not finish while shutdown's stop is paused. A 500 ms bound only limits how long a regression takes to show; the correct code never finishes inside it;
    - the paused render is released and lands;
    - after shutdown, no window is visible and the registry is empty.

    With an unshared stop (mutant N31, the round 3 behaviour), this test fails.
16. *a failed draft's late render is closed even when the same draft is retried meanwhile* (round 4, modelled on probe N). Steps:
    - the failure's save is held;
    - the same draft is connected again, so an entry with that ID is back, owned by a fresh context;
    - the old attempt's paused render lands in its dropped context;
    - once the save is released, the tail closes that context's windows.

    The tail keys on context ownership, not on whether an entry exists. With the entry-based check (mutant N28), this test fails.
17. *a removed live entry's windows close as soon as its session fails, before the stop* (round 5, modelled on probe P1). Steps:
    - a real controller reaches ready, with a visible window and no status;
    - the row is deleted, and the window stays;
    - the transport fails, and the attempt's stop pauses on `stopWillRetireMountForTesting`;
    - during the paused stop the window is already closed;
    - it is still closed after the stop.

    With `case .failed, .stopped: return true` restored (mutant N32), this test fails.
18. *a removed entry whose attempt fails to start closes its windows before the stop* (round 5). A fake attempt's start fails after its row was deleted, and its stop is paused. The window is closed through `markDisconnected` before the stop. With no discard for a missing entry in `markDisconnected` (mutant N33), this test fails.
- Every new test hook is installed per controller through `makeSessionControllerAttempt(…, configureController:)`. No global hook is added, so nothing can leak into other tests.

## Limitations

- Status changes are not spoken. VoiceOver reads the status with the window (accessibility title on macOS 26, accessibility help everywhere), but nothing posts an announcement when the status changes. Out of scope.
- "Revision N" is the applier's last applied revision at the transition, not the drawn revision. It can briefly lead or trail what the window draws (see the Implementation section). The line is always marked `(stale)`.
- A dropped context's windows close at once and again after its attempt's shared stop has finished. An attempt only renders into its own request's context, so no other attempt can reopen them. Between a render in flight landing and the tail's second close, the window can briefly show again with no status. This lasts only until the stop finishes, and the stop retires the render owner.
- After REPLACED, the replica is reset. A disconnect before the replacement snapshot is ready reads `disconnected — showing data from revision 0 (stale)`.
- Accessibility on `macos-15` (CI) is covered by the asserted accessibility help. Whether that release also folds the subtitle into the accessibility title was not observed locally.
- PX-022 itself, which will use this in srtop's flows (detached cached inspection, disabled process actions, replay and replacement semantics), is still to do.
