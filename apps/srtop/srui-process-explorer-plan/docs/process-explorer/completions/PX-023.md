## Design reading

- D1 §19, §19.1: SSH provides host-key verification and user authentication; the client uses a fixed subsystem, never a shell-interpolated command, relies on the user's `ssh`/agent/`known_hosts`, and fails closed on host-key changes "according to normal SSH policy". The form therefore produces argv elements only and keeps `StrictHostKeyChecking=yes`.
- D1 §25: "SRUI does not weaken host-key checks and does not define an 'accept unknown host silently' mode." The alert stops; it never offers to trust, and (round 5) says nothing about the key beyond what the local known_hosts files hold.
- D1 §22.1: the client is SSH adapter plus renderer; remote data must not drive local behaviour. The form is local chrome. No remote app can open it, prefill it or choose a destination: `SavedConnection`/`ConnectDraft` are written only by the user's form and the local file. Correction (round 2): round 1 did let remote data choose local chrome. It classified every failure string, including a server's `SERVER HANDSHAKE_REFUSED` detail, so a server could raise the host-key alert and its `ssh-keygen -R` advice. Round 2 classifies only `ssh`'s own exit (see "Round 2").
- D2 T19–T20: `SSHTransport` and the capability handshake are reused unchanged. D2 T38: host, optional port, remote user and Connect, relying entirely on existing SSH credentials, with host-key behaviour "visible to the user, not silently bypassed".

## Implementation

### `client-macos/ConnectionManager/ConnectionEndpoint.swift` (new)

- `ConnectionEndpoint.parse(host:user:port:)` returns `Result<ConnectionEndpoint, ParseError>`. Only leading and trailing whitespace is dropped. The Host field also accepts `user@host`, `host:port`, `[v6]` and `user@[v6]:port`; a user or port given in both places must agree (`conflictingUser`, `conflictingPort`).
- Host: ASCII `[A-Za-z0-9._-]`, not starting with `-` or `.`, at most 253 characters (RFC 1035 text form). It may be an `ssh_config` alias. IPv6 must be bracketed and pass `inet_pton(AF_INET6)`, with an optional `%zone` of `[A-Za-z0-9._-]`; the brackets are stripped for `ssh`. A bare IPv6 address (`::1:22`) is refused because its end is ambiguous. `://` is refused as a URL.
- User: ASCII `[A-Za-z0-9._-]`, not starting with `-` or `.`, at most 64. Port: one to five ASCII digits, 1–65535; `+22`, `-22`, full-width digits and `000022` are refused. Name: local only, at most 128; an empty name defaults to `user@host[:port]`.
- Every `ParseError` has a user-facing `description`, which is what the form shows. A space or control character is named by its code point.
- `validate(savedHost:user:port:)` re-checks a stored entry, port included since round 2. `displayString` brackets IPv6 for the Connections list.
- Deliberate back-compat tightening: an entry saved before PX-023 whose host the form would no longer produce still loads and is listed. Examples are `user@host` in the host field, `host:port`, a trailing space, a non-ASCII name, or port 0. `connect(id:)` refuses it with "This saved connection’s endpoint is invalid: … Remove it and add it again." The test "a tampered saved entry is refused before it can become argv" covers `alice@host.example`, `host.example ` and port 0.

### `client-macos/ConnectionManager/HostKeyRejection.swift` (rounds 1–4; removed in round 5)

- Classifies OpenSSH's own `sshconnect.c` text: `changed` (`REMOTE HOST IDENTIFICATION HAS CHANGED`, `has changed and you have requested strict checking`, `POSSIBLE DNS SPOOFING DETECTED`), `revoked`, `unknown` (`host key is known for … you have requested strict checking`), or `unverified` (`Host key verification failed`). Anything else is not a host-key failure.
- `alertMessage(for:sshMessage:)` names the endpoint and the known_hosts name (`[host]:port` for a port other than 22), says SRUI never adds or replaces a key, says how to check it outside SRUI (`ssh-keygen -R '…'`, connect once from Terminal), and appends OpenSSH's text, which includes the offered fingerprint for a changed key.

### `client-macos/ConnectionManager/ConnectionManager.swift`

- `ConnectDraft.endpoint`, `validationMessage` and `savedConnection` use `ConnectionEndpoint`.
- `ConnectionManager.sshConfiguration(for:)` (nonisolated, pure) is the one configuration every attempt uses, extracted unchanged from `beginAttempt`. The production factory still builds `SSHTransport(configuration: request.configuration)`.
- `connect(id:)` refuses an entry whose stored host/user no longer validate (`invalidInput`, "This saved connection’s endpoint is invalid: …"), before any attempt or argv exists.
- (Rounds 1–4, removed in round 5.) `recordFailure` turned a host-key failure into `ConnectionAlert.Kind.hostKeyRejected`, titled "Host Key Not Trusted". It reads the entry before `markDisconnected` forgets a never-connected draft. Other failures keep "Connection Failed" with the original message. `presentAlert` folds a host-key failure into a pending REPLACED disclosure exactly as it does a connection failure.

### `client-macos/ConnectionManager/ConnectionManagerView.swift`

- `ConnectSheet` (now internal, for the native test): Host (prompt `host, user@host:port or [::1]`), Remote User, Port (`optional`), Name (`optional`); the validation reason in red; Cancel and Connect at the bottom as the cancel and default actions. Connect is disabled and `submit()` re-checks validity. The NavigationStack and toolbar were replaced by a plain stack so the buttons are the sheet's own controls. The row endpoint uses `ConnectionEndpoint.displayString`.

### Round 6 (bounds of the local lookup; `UpdateHostKeys`)

Independent verification of `f901de4e` (`verify5-verification-result.json`) confirmed the round-5 design: all 54 of its spoof probes produced exactly the benign app text. It FAILED on two bounds issues and listed three cheap hardening items. All are fixed here:
- F1, the `timeout-removed` mutant survived: its test hung until the 900 s mutant timeout, because a continuation that is never resumed cannot be cancelled. Fixed in the tests with `TestDeadline.race` and a hung fake `ssh-keygen` whose exact PID must be gone (see "Tests → Round 6").
- F2, the 256 KiB output cap never took effect. Stdout was read only at exit, so a child writing more than one pipe buffer (about 64 KiB) blocked until the 5 s deadline, and a true "present" hint was lost (the verifier measured 500, 1000 and 3000 entries; each gave no hint after 5 s).
  - `BoundedProcess.run` now drains stdout on its own thread while the child runs. Exceeding the cap stops reading, ends the run with no result, and stops the child.
  - The result is delivered only when both the exit and the end of the drain have been seen.
  - `ssh-keygen -F` is read by exit status alone, with stdout sent to `/dev/null`, so the number of matching entries no longer matters.
- SIGKILL escalation: stopping a child (deadline or cap) sends SIGTERM to its exact PID, then SIGKILL to that PID after 500 ms unless the termination handler has already recorded its exit. The remaining PID-reuse window, between Foundation's reap and that record, is marked `lc-debt` in the code.
- `UpdateHostKeys`: `ssh -G` reported `updatehostkeys true` for the production argv, so OpenSSH itself could add a trusted server's rotated keys to known_hosts after login, and the hint's "SRUI never adds or changes host keys" was not fully true.
  - `-o UpdateHostKeys=no` is now a posture flag, emitted before any extra option, and `UpdateHostKeys` is a blocked extra key (any case).
  - No reason not to pin it was found: SRUI's trust model is explicit, and rotating keys is a choice the user can still make with `ssh` directly.
- Limits, stated plainly: each child (`ssh -G` and each `ssh-keygen -F`) has its own 5 s deadline. The worst case is therefore 5 s × (1 + the number of readable known_hosts files) before the alert shows. Only the user's own `ssh_config` can approach it, for example with a slow `Match exec` or many known_hosts files. stdout per child is capped at 256 KiB.
- Note wording: the "Tests" section's rounds 1–4 parts are labelled historical.

### Round 5 (user decision: no alert content from `ssh`'s output)

- Removed:
  - `HostKeyRejection.swift` (the stderr classifier) and `LocalHostKeyRejection.diagnose`;
  - `ConnectionAttemptEvent.hostKeyRejected` and `ConnectionAlert.Kind.hostKeyRejected`;
  - the "Host Key Not Trusted" title and all of its advice (`ssh-keygen -R`, "connect once from Terminal").
  - The app never generates trust-changing advice.
- `ConnectionManager.swift`:
  - When `ssh` exits 255 before any SRUI byte (`SSHTransport.localFailureBeforeStream()`, kept, now only a trigger), the attempt yields `.sshFailedBeforeStream(stderr:hint:)`, or throws `SSHFailedBeforeStream` from `start()`.
  - `recordFailure` shows a blocking **Connection Failed** alert: "SRUI could not connect to <endpoint>.", the hint if there is one, then "ssh reported (this text can include messages from the server):" and `ssh`'s stderr verbatim (`sshFailureMessage`).
  - Every other failure keeps its message under the same title. Nothing the server or `ssh` printed decides the title, the kind or any app-written word.
  - PX-022's `ContinuityRecorder` in `ProcessExplorerShellTests.swift` names the new event.
- `KnownHostsHint.swift` (new) holds the local facts:
  - `SSHKnownHostsLookup` runs `ssh -G` with the connection's exact argv. From its output it reads `hostname`, `port`, `hostkeyalias`, `userknownhostsfile` and `globalknownhostsfile`, so nothing about `~/.ssh/known_hosts` is hard-coded.
  - It then runs `/usr/bin/ssh-keygen -F <name> -f <file>` on each readable file; exit 0 means present, 1 means absent. Hashed entries work.
  - `<name>` is `host`, or `[host]:port` for a port other than 22, or `HostKeyAlias` verbatim, as `sshconnect.c` files it.
  - Both commands are argument vectors with no shell. stdin, stdout and stderr are set before `run()`. Each is bounded by 5 s (SIGTERM to the exact child on expiry), awaited through the termination handler, and run from the attempt actor, never the main actor.
  - Any launch failure, non-0/1 status, timeout, or `ssh -G` path that is not absolute (it prints lists unquoted, so a path with a space is unrecoverable) gives no hint at all.
  - Hint texts:
    - absent: "<name> is not in your known_hosts files (<files>). SRUI never adds or changes host keys. If you mean to trust this host, verify its key fingerprint out of band, then add the key with ssh yourself."
    - present: "A key for <name> is in <file>. SRUI will not change it."
  - Both are true whatever the server sent.
- Kept: `StrictHostKeyChecking=yes`, `BatchMode`, pinned `LogLevel=INFO` (its final lines reach the quoted stderr), posture-first option order, the case-insensitive blocklist, and all parser, bound and NUL work.
- Process note: the round-4 `pkill` incident is disclosed in "Commands → Round 4". There was no `pkill` or `killall` in round 5; every process stopped was an exact PID this run started.

### Round 2 (verifier findings F1, F2 and the saved port)

- F1, `ConnectionEndpoint.swift`:
  - `firstDisallowedScalar(in:)` is the first rule for every field (host, user, port and name) and for saved host and user. It refuses NUL and every other scalar of category control (C0, DEL, C1), format (zero-width, BOM, bidi override), line or paragraph separator, surrogate, private-use or unassigned, as `ParseError.controlCharacter(Field, Unicode.Scalar)`, e.g. "Host can’t contain a control or invisible character (U+0000)."
  - `trimmed(_:)` now drops only spaces (Unicode `Zs`), tab, LF and CR at the ends. `CharacterSet.whitespacesAndNewlines`, used before, also trims U+200B, NEL and U+2028, so an invisible scalar at an end was silently dropped rather than refused.
  - `validateIPv6` refuses any literal containing a NUL, and calls `inet_pton` only when `strlen` of the C string equals the UTF-8 length, so it can never pass on a prefix. The zone (ASCII `[A-Za-z0-9._-]`), name, user and port rules never admitted a NUL; they are now also behind the field-wide check.
- F2:
  - `SSHTransport.localFailureBeforeStream()` (`TransportSSH/SSHTransport.swift`) returns `SSHLocalFailure(status:stderr:)` only when the `ssh` child exited by itself with status 255, `ssh`'s own error status, before a single byte arrived on stdout, the SRUI stream. A `StreamByteRecord` set by the stdout reader tracks those bytes. A SIGTERM from our own `close()` is never 255.
  - `ConnectionManager.swift`:
    - `LocalHostKeyRejection.diagnose(_:)` classifies only that stderr with `HostKeyRejection`.
    - `SessionControllerConnectionAttempt` keeps the `SSHTransport`. On a lifecycle `.failed` it yields the new `ConnectionAttemptEvent.hostKeyRejected(_, sshMessage:)` when there is a local diagnosis, and `.failed(description)` otherwise. A `start()` that throws becomes `LocalHostKeyRejection` the same way.
    - `recordFailure(_:connectionID:token:hostKey:)` raises the host-key alert only when given that verdict, and never reads the failure text for phrases. A server refusal stays "Connection Failed" with its own text, and the alert's "OpenSSH reported:" now quotes `ssh`'s stderr alone.
- Saved port: `validate(savedHost:user:port:)` refuses port 0. Port 65536 cannot be decoded into `UInt16`, so such a file fails to load (`persistenceFailed`) and nothing connects.

### Round 3 (banner as host-key verdict; unbounded error echo)

- `TransportSSH/SSHConfiguration.swift`: every `ssh` now runs with `-o LogLevel=ERROR`, appended with the other posture flags after `extraOptions`. `LogLevel` is in `blockedExtraOptionKeys`, so nothing can raise it again.
  - OpenSSH prints the userauth banner only at INFO and above, so the server's banner (and any other INFO-level text a server can author, such as a disconnect reason logged at INFO) never reaches the stderr that `localFailureBeforeStream()` reports.
  - Checked live and on the command line (`impl3-loglevel-cli.log`, `ssh` 10.2p1):
    - "Host key verification failed." and the unknown/changed lines are `error()`/`fatal()` and still appear;
    - "Permission denied (…)" still appears (`impl3-banner-authenticationFails.txt`);
    - "ssh: connect to host … Connection refused" and "Could not resolve hostname" still appear at ERROR (`impl3-connection-refused.txt`).
  - Every other `SSHTransport` user gets the same flag: `RendererDemoApp --ssh`, and the SSH tests. Their assertions read "Host key verification failed"/"exit code" or stubs, and all pass in the full run.
- `ConnectionManager/HostKeyRejection.swift`: the classifier is structural, not a phrase search.
  - The verdict must be `ssh`'s last stderr line, exactly "Host key verification failed.", which only `ssh`'s fatal exit writes.
  - The kind comes from the line OpenSSH writes just before it: `No … host key is known for … and you have requested strict checking.` gives unknown; `Host key for … has changed and you have requested strict checking.` gives changed; `impersonate this host.` together with the revoked banner gives revoked. Anything else ending with the verdict is unverified.
  - This matters because a server's `SSH_MSG_DISCONNECT` reason is logged at ERROR ("Received disconnect from …: <text>"), and `ssh` then ends with "Disconnected from …"; an authentication failure ends with "Permission denied …". Server text before ssh's own last line therefore never classifies, even at ERROR.
  - The two layers are each needed. LogLevel alone cannot stop a disconnect reason. The structural check alone cannot stop a banner followed by a silent exit 255, where the banner's own last line would end stderr; the live `subsystemExits255` case shows this.
- `ConnectionManager/ConnectionEndpoint.swift`:
  - Every bound now counts Unicode scalars, not `Character`s: the host field at most 326, host 253, user 64, port 5, name 128.
  - Any field over 4096 UTF-8 bytes is refused before it is trimmed or scanned. `utf8.count` is constant time, so a 1,000,000-scalar grapheme is refused at once.
  - Every `ParseError` description echoes at most 32 scalars of input and then "…" (`ParseError.excerpt`), including a `Character` in `invalidHostCharacter`/`invalidUserCharacter`, an `invalidIPv6` literal, and both sides of `conflictingUser`/`conflictingPort`.
- Test hygiene: an early mutant run parked for 27 minutes in `LiveSSHD.shutDown()` → `SSHTestSupport.terminate` → `Process.waitUntilExit()`. That call services the main run loop, and this suite is `@MainActor` (`impl3-wedge-sample.txt`; sshd was already gone).
  - The run was interrupted with SIGINT, the script restored the sources, and the reaper's dry run and real sweep found nothing to clean.
  - The live suite now tears its fixtures down on a detached task (`shutDownOffMainActor()`), so the wait never runs on the main actor.
  - Both PX-023 parse suites gained a `.timeLimit(.minutes(1))`, and the mutation script a 900 s per-mutant timeout that counts a wedge as a survivor.

### Round 4 (DISCONNECT text as verdict; diagnostics; option order)

Design (the coordinator's round-4 design), checked against real `ssh` 10.2p1 before it was relied on:
1. `-o LogLevel=INFO` is pinned instead of ERROR (`TransportSSH/SSHConfiguration.swift`).
   - At INFO, `ssh` ends every peer-initiated failure with a line of its own (`impl4-probe-disconnect-info-cli.log`, the verifier's fake server modes):
     - each DISCONNECT ends with `Disconnected from 127.0.0.1 port P`, after the server's reason;
     - a TCP close ends with `Connection closed by 127.0.0.1 port P`;
     - a silent server ends with `Connection timed out during banner exchange` and then `Connection to 127.0.0.1 port P timed out` (`impl4-probe-silent-cli.log`).
   - Pinning on the command line means the user's `ssh_config` cannot lower the level, which would hide those lines, or raise it, which would add debug lines after the verdict. The `ssh -G` test with a hostile `-F` shows `loglevel INFO`.
   - `LogLevel` stays a blocked extra option.
2. The last-line rule stays: the verdict must be `ssh`'s last stderr line, exactly "Host key verification failed.".
3. Hard exclusion (`HostKeyRejection.swift`): if any line starts with `Received disconnect from ` (written by `ssh` itself, before any server text), nothing is classified. This closes F1 even if the following line were ever hidden again (round 3's ERROR transcripts are now negative fixtures).
4. Protocol order for the banner: the userauth `Banner` follows key exchange, so a server whose key is unknown or changed never gets to send one.
   - Confirmed with a real sshd whose `Banner` carries a marker (`impl4-probe-banner-order.log`): with an empty or a changed known_hosts, stderr holds only `ssh`'s refusal and never the marker.
   - Live tests `unknownKey` and `changedKey` assert this.
5. Option order (F3): every posture and configuration option (`ClearAllForwardings`, `ExitOnForwardFailure`, `StrictHostKeyChecking`, `LogLevel`, `UserKnownHostsFile`, `BatchMode`, `ConnectTimeout`, `IdentitiesOnly`) is now emitted before any extra option. `isBlockedExtraOptionKey` matches case-insensitively. The `ssh -G` test shows that no lower-case or mixed-case extra option, and no hostile `-F` config, overrides any of them.
   - The order affects only options that come before `-p`/`-l`/`-i`, which stay at the end.

Design outcome: confirmed, with one consequence that conflicts with an earlier test.
- With INFO pinned, a trusted server's banner is printed again. That is the residual the design names in point 4: a trusted server the user authenticated to, which sends a banner and then has its subsystem exit 255 without a byte or a word.
- Measured (`impl4-probe-banner-order.log`, trusted, `-E none`): stderr is the banner alone, so its last line can be the verdict, and that run is classified as "Host Key Not Trusted".
- Round 3's live case `subsystemExits255`, which expected "Connection Failed", cannot hold under this design. It now asserts only safety (no connection, known_hosts unchanged) and records which alert appeared.
- Proposed follow-up, not implemented (it needs approval): run `ssh` with `-E <private log file>`. The same probe shows that `-E` sends `ssh`'s own log, including the verdict and the INFO final lines, to the file, while the banner and any remote stderr stay on stderr.
  - Classifying only the log file would close this residual, and the authenticated-subsystem-stderr one as well.
  - It needs `SSHTransport` to create a 0600 file in a private directory, read it on failure, and remove it at close.

Also changed:
- `ConnectionLauncherLiveTests.LauncherProbe` is internal and takes a `connectTimeout`.
- The hostile banner starts with a marker line.

## Tests

### Round 6

- `BoundedProcessTests` (new):
  - 100 KiB of output, past one 64 KiB pipe buffer, is drained while the child runs and returned in milliseconds;
  - output of exactly 256 KiB (the cap) is returned whole;
  - 256 KiB + 1 gives no result, at once and not at the deadline.
- `KnownHostsLookupTests`:
  - A hung `ssh -G` (an assessed stub that `exec`s `/bin/sleep 30` as its own PID) ends at the 300 ms deadline, and that PID is gone.
  - A hung `ssh-keygen` that ignores SIGTERM (`trap '' TERM; exec /bin/sleep 30`) gives no hint, and its exact PID is gone: only the SIGKILL after the 500 ms grace can do that.
  - 500 and 3000 matching entries (about 49 KiB and about 290 KiB of what `ssh-keygen -F` would print) answer "present" in well under 3 s.
  - `/usr/bin/yes` as `ssh` is stopped by the output cap in under 3 s.
  - Every lookup and `BoundedProcess` call in these suites goes through `TestDeadline.race`. ## Limitations

- The native form test drives `ConnectSheet` hosted directly in a window rather than through **Add Connection** in the full Connections window, and reaches Connect by its Return key equivalent: SwiftUI draws its buttons without `NSButton`s, and the in-process accessibility tree of the hosting view is empty without an assistive client. The sheet-to-`manager.connect(_:)` wiring in `ConnectionManagerView` is one unchanged line; the manager path is covered by the live tests. Manual check: run `client-macos/.build/debug/RendererDemoApp` with no arguments, click **Add Connection**, type `host;id` (expect the inline message and a disabled Connect), then a real host.
- The live tests substitute only the identity file and known_hosts path in the manager's configuration, because the ephemeral sshd's key cannot be in the user's `~/.ssh/known_hosts`. Every other option is asserted equal to `sshConfiguration(for:)`. The user's own `~/.ssh/config` still applies to every `ssh` the form starts, as before.
- Host-key messages (round 5): SRUI does not interpret `ssh`'s output at all. Rounds 1–4 classified it and were spoofed four ways: a server refusal, a pre-auth banner, a DISCONNECT reason, and a KEXINIT name-list. Each alert now has the same title and the same app-written text for the same known_hosts state, whatever the peer sent. The live, fake-server and spoof tests assert this. The user reads `ssh`'s own words, labelled as possibly the server's. The round-4 trusted-server residual and the `-E` proposal are moot.
- The hint reflects the files `ssh -G` reports and the name it would use. `CheckHostIP` entries for the address are not consulted. A known_hosts path containing a space disables the hint, because `ssh -G` prints paths unquoted. A user `ssh_config` that changes files between the lookup and the attempt is not modelled.
- The hint is shown for any `ssh` exit 255 before the stream (for example connection refused), because it is a fact about known_hosts, not a diagnosis of the failure.
- The Name field admits invisible letters and marks that are not in a refused category (U+3164 HANGUL FILLER, U+115F, U+034F, U+FE0F) and U+FFFD. The name is local display only and never reaches `ssh`.
- An IPv6 zone that is not an interface name (`%h`, `%-`, `%.`) is accepted by the zone grammar. OpenSSH drops a scope it cannot resolve (`ssh -G` shows the bare address), so it only names the destination less precisely; it cannot inject an option.
- The `RendererDemoApp --ssh/--user/--port` developer command line (used by `apps/srtop/run.sh ssh`) still passes its arguments as given, behind the existing `--`. It does not go through this form's validation.
- One connection window, no fleet management, no stored secrets, no new retry or reconnect semantics, as the ticket requires.
