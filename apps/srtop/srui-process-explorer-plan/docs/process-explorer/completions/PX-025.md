## Design reading

- D1 §31.4: inject 0/100/300/600 ms RTT; local feedback (text entry, caret, scrolling, …) MUST NOT acquire one-RTT latency; server-dependent input-to-visible latency is measured separately. Interruption is one of the controlled impairments.
- D1 §31.3 / §12.2: for an identical mutation stream, wire bytes and message count must not scale with the client's refresh cadence; local repaint count may differ.
- D2 T28 (scrolling cached ranges stays local), T29 (typing/caret local, delayed transport test), T34 (the §31 benchmarks). T34's §31.4 driver (`client-macos/Benchmarks/NetworkBenchmark.swift`) proves the generic property for the coding-agent fixture over the in-process `BenchmarkTransport`; the runtime half of §31.3 is `server-rust/sessiond/tests/conformance_frame_independence_test.rs` and `FrameIndependenceConformanceTests.swift`. PX-025 reuses their proof pattern (a causal held-response proof for local feedback, a two-sided non-vacuous cadence comparison) and applies it to srtop over the real SSH path. No second benchmark driver, metric contract or report was added; `benchmarks/` and `client-macos/Benchmarks` are unchanged.

## Why a separate package

srtop's own package is audited by PX-008 (`apps/srtop/tests/no_process_control_test.rs`): its sources may not name `Command`, `Child`, `kill`, `UnixStream`, `connect`, `unsafe`, …, and its targets are exactly the library and `srtop`. The worker spawns and kills its own children and the relay opens outbound sockets, so both live in a new package, `apps/srtop/demo` (`srtop-demo`), whose `Cargo.lock` is srtop's lock plus the one new path package (no new or changed external crate; checked by diffing the `name =` lists). Nothing in it is linked into `srtop`; the audit is unchanged and still passes. No srtop source, SDK, runtime, protocol, registry, proto, framing or generated file changed.

## Implementation

### `srtop-demo-worker` (`demo/src/worker.rs`, `demo/src/bin/srtop-demo-worker.rs`)

| Mode | Workload | Limit (accepted at, refused past) |
| --- | --- | --- |
| `cpu` | `--threads` spinning threads | 1–4 |
| `memory` | `--mib` MiB, every page touched (resident) | 1–256 MiB |
| `threads` | `--threads` parked threads (64 KiB stacks) | 1–64 |
| `short-lived` | `--count` children, one per `--interval-ms`, each living `--lifetime-ms`, at most 8 alive, reaped | 1–64; 1–2000 ms; 10–1000 ms |
| (all) | `--duration-ms` hard deadline; `--fail-after-ms` ≤ duration | 1 ms–60 s |

- Test-owned: refuses (exit 2) without `--srtop-test-owner TOKEN` and the same `TOKEN` in `SRTOP_DEMO_WORKER_OWNER`; the token must be `srtop-demo-[a-z0-9-]{1,53}`. The flag pair stays in the argument vector of the worker and of every short-lived child.
- Ends by itself: the main thread waits on `recv_timeout(duration)` and the binary then calls `process::exit`, whatever the workload threads do (exit 0). Its stdin is a lifeline: `stop` → exit 20; EOF or error (the owner exited, however) → exit 21. `--fail-after-ms` → exit 22. A short-lived child's stdin is a pipe from its worker, so the chain unwinds; on any exit the worker kills (its own `Child` handles) and reaps the children still running.
- Bounds are validated, never clamped; the same validation runs in the harness before anything is spawned.

### Cleanup handles (`demo/src/harness.rs`)

- `DemoWorker` owns the worker's unreaped `Child` and its lifeline. `stop(grace)` writes `stop` and waits; `kill()` closes the lifeline first (so an unsignalled worker ends by itself), then sends SIGKILL through the handle only while that PID still carries this run's owner token; `Drop` does the same, so a test that fails cleans up as it unwinds.
- `processes_with_owner(token)` finds a run's processes by the exact `--srtop-test-owner TOKEN` pair: `/proc/*/cmdline` and `stat` state on Linux, `ps -ww -A -o pid=,stat=,command=` elsewhere. Zombies count as ended. No name is ever matched.
- `srtop-demo workers --duration-ms MS [--cpu-threads N] [--memory-mib N] [--threads N] [--short-lived COUNT]` is the harness the interruption tests stop: it prints `owner TOKEN` and `worker MODE PID` and waits. It installs no signal handler; its workers' lifelines close when it dies by any signal.

### `srtop-demo relay` (`demo/src/relay.rs`)

- Listens on an owner-only (0600) Unix socket — `srui-ssh-bridge` refuses one group or others can reach (found when the first native run's ssh exited 1: `permissions 0755 allow group/other access`) — and joins each client to the upstream socket.
- Each direction is a delay line: a reader thread timestamps every chunk and a writer thread releases it at read time + RTT/2 (`rtt - rtt/2` downstream), in order, never waiting for the previous write. Bytes are counted per direction. `cut` shuts both sockets of every live connection and the relay keeps accepting. RTT ≤ 10 s.
- The accept loop polls (`lc-debt`, 2 ms) so `stop()` never depends on waking a blocked `accept`: a debugging relay whose socket directory had been removed hung in `stop()` waiting for a self-connect that could not succeed (`impl1-leftover-relay-sample.txt`); `a_relay_stops_even_when_its_socket_path_is_gone` pins the fix.
- No root, `tc`, `dnctl`, `pfctl` or sudo anywhere.
- In the native tests the sshd subsystem is `Subsystem srui <srui-ssh-bridge> <relay socket>`, so every byte between the generic client and srtop crosses the relay.

### Scenarios (`demo/src/wire.rs`, `demo/src/scenario.rs`, `srtop-demo scenarios`)

- `wire::Replica` is the minimal replica client of `continuity_test.rs` (HELLO/RESUME, one snapshot envelope, every commit applied), with standard `TEXT_EDIT` events. Each attach uses a fresh `client_instance_id`: reusing one across HELLOs continued the same event sequence and srtop (correctly) treated the edits as duplicates.
- `remote_results`: `--fake-repeated-names` (60 rows); each trial sends one filter or search `TEXT_EDIT` and times it to the committed `FILTER_STATUS` / `SEARCH_STATUS` naming the term. The term is the first of `worker|w|wor|work` the status does not already name, because the filter and search state is the session's and a commit in flight can re-state an earlier client's term (this produced a 0.5 ms "result" at 100 ms RTT before the rule).

- `collector_failure`: `--fake-sequence`; the last healthy rows before the scripted failed scan (step 3), the rows, status and freshness line during it, and the rows after recovery, at 300 ms RTT.
- `srtop-demo scenarios --srtop PATH [--trials N]` starts both fixtures in a private `/tmp/srtop-demo-*` directory and prints one JSON report.

## Limitations

- The worker's limits are its own: validated sizes and a deadline its main thread enforces; no kernel `setrlimit` (the package is std-only and uses no FFI). A worker that is SIGSTOPped does not reach its deadline until continued.
- Local latency is the native state change (field editor text, selected range, viewport row and cell) timed around the AppKit call, not pixels on screen: the composited-pixel proof is T34's §31.4 full-mode benchmark, which this does not repeat. IME, selection, hover, pressed and menu opening are not re-measured for srtop (T34 covers them generically); srtop's local interactions here are typing, caret and scrolling, as the ticket lists.
- The relay adds pure delay: no bandwidth cap or loss (T34's impairment cases cover those generically). An idle relay polls `accept` every 2 ms (`lc-debt`).
- The cadence test varies render cost and present batching through the existing test interceptor; it cannot change the display's refresh rate.
- The live `/proc` demonstration runs on Linux only; on macOS srtop has no live source.
- CI's change to `.github/workflows/ci.yml` makes a push of this branch use the conservative full pre-push profile.
