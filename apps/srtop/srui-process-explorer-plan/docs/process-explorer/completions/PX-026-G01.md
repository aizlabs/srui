## User decisions applied

1. **The named Linux environment is the devbox container.** It is pinned by image label, Debian
   version, kernel, Rust toolchain and binary digests (below).
2. **The user runs the clean-account walkthrough.** It is
   `apps/srtop/r1/clean-account-walkthrough.sh`, with instructions in `CLEAN_ACCOUNT_WALKTHROUGH.md`.
3. **Distribution is build from source with the pinned toolchain.** The binary carries only the
   linker's ad-hoc signature, nothing is notarized and no Apple credentials are involved. The R1
   notes say signed or notarized distribution is out of scope.
4. **The user runs a VoiceOver checklist of about ten minutes.** It is
   `apps/srtop/r1/voiceover-keyboard-checklist.md`, set up by `checklist-session.sh`, and holds the
   four outstanding manual checks.

## Privacy and disclosure audit

| Surface | Finding |
| --- | --- |
| Command-line and path collection | srtop reads a process's arguments, executable and working directory only for the one selected instance, only on demand, through the inspector's worker. It never logs them (`command.rs`, PX-014; `Sensitive`'s `Debug` prints only a length). Environment variables are never read: no `environ` access in `src/`. A selected process's command line is shown to the same reader `ps` would show it to, which is by design and stated in R1.md. Live canary: shown on selection, absent from every log. |
| Logs | srtop writes only `srtop: … not published: {error}` lines and peer and connection errors to stderr. The bridge logs to stderr through tracing (§20.1). The client logs errors to stderr and `os_log` (`org.srui.Session`); info logs are opt-in. In the live run none of these held the canary. The client's unified log held only failure descriptions like "transport ended: …". |
| Saved endpoints | `~/Library/Application Support/SRUI/saved-connections.json` (PX-024) holds the endpoint, its label, the last session ID and the revision; no credential, since authentication stays OpenSSH's. It was not opened here: the real store was not touched. `srui-r1-install.sh uninstall --purge-settings` removes only it and its `.unreadable` backup. |
| Diagnostic bundles | None exist in R1. Advanced diagnostics are PX-076 to PX-083 and out of scope. |
| Walkthrough result file | Records only versions, commands, exit codes and timestamps, with home as `~`, checkout as `<checkout>` and host as `<host>`. The walkthrough audits the file itself before writing its summary. The dry-run result is committed as evidence and passes the audit. |
| Install prefix | The `MANIFEST` and the binary were audited. The binary embeds the builder's home path as build paths, reported as `BINARY-PATH` information and documented as a known gap. |
| Committed evidence | `evidence/PX-026-G01/` passes the audit. |

## Limitations and follow-ups

- **A server refusal gives no reason.** When the server refuses an incompatible client offer, the
  client can say only that the connection closed. A reason needs a new `HandshakeRefusalReason`
  value, which is a protocol prerequisite. It is listed in R1.md and not built here.
- **Window identity across a resume.** In the connection manager, the resumed session's window is
  a different `NSWindow` (`same NSWindow: false`). This is recorded, not asserted. Checklist item 9
  watches its effect.
- **CI.** The live checks and the walkthrough need Docker and are not in CI. `selftest.sh` runs
  in `apps/srtop/test.sh`, the Darwin pre-push path, not in a CI job.
- **Tooling not run.** `shellcheck` is not installed here. The devbox's apt packages are not
  pinned.
- **Known follow-ups.** They are listed in R1.md: the `SSHTestSupport.terminate` wedge risk, the
  AF_UNIX lost-FIN audit, the pre-push hook's display, the load-sensitive PX-025 and PX-010-G01
  timing tests, PX-023's `posix_spawn` lc-debt, G02 O2 and the T35 capability-only check.
