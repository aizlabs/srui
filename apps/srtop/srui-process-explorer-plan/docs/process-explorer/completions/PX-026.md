# PX-026 implementation evidence

Ticket: PX-026, Demonstrate semantic inspection without external IPC. Branch `codex/PX-026-automation`, based on `b0dfa863feddfd6efd6542a000f028db040213d9` (the PR #114 merge of PX-025). Evidence directory: `process-explorer-run/20261108T234755-px011/PX-026/` in the orchestrator scratchpad. Every log is prefixed `impl1-`.

## Design reading

- **D1 §22.9.** The client keeps a read-only semantic-tree API with stable node identities, roles, labels, values, hierarchy, state and advertised actions. A local consumer writes `find(role=button, label="Restart").activate()`, never `click(x, y)`. The surface is semantic: it MUST NOT expose `NSView` pointers or classes as identity. Automation actions MUST travel through the normal SRUI event path and the server's authorization checks. They MUST NOT mutate the authoritative tree directly or bypass `enabled` or capability state. An XPC surface SHOULD stay disabled until its authorization model is specified.
- **D2 T35.** T35 is the in-process API: `client-macos/Accessibility/Accessibility.swift` (`SemanticInspector`, `SemanticTreeSnapshot`, `SemanticNodeSnapshot`, `SemanticNodeHandle`), served by `SessionController.makeSemanticInspector()`. Its handles call `performSemanticAction`, which uses the same `enqueueSemanticAction` → `validateSemanticAction` → `send*` → `EventOutbox` path as `enqueueNativeSemanticAction`, the native renderer trampoline (`renderer.onInteraction`). Validation checks the epoch, that the session is active, the negotiated `standardWidgetsV1` capability, that the node exists, `enabled`, the registry emits matrix and the selection mode. T35 has no XPC or IPC surface. T35 already covers what PX-026 needs, so no generic facility, protocol message or SDK change was added.
- **D2 T24.** T24 covers event settlement: `event_seq` is contiguous per client instance, and each event is settled by `ServerEventAck` (`settled_event_seq`, status, echoed `event_id`). PX-026 proves that settlement is identical at the wire for automated and native actions.
- **The existing T35 coverage.** `SemanticInspectionAutomationTests` and `SemanticInspectorTests` prove the generic properties over a pipe fixture. PX-026 applies them to srtop over real SSH, in the unchanged generic client.

### `ProcessExplorerAutomationTests.swift`

The new file is `client-macos/Tests/SRUITests/ProcessExplorerAutomationTests.swift`. It is an `extension ProcessExplorerShellTests`, so it shares that suite's `.serialized` trait and its real-SSH fixture. The only change to `ProcessExplorerShellTests.swift` makes `Harness`, `launch` and `shutDown` internal instead of private.

The tests:

- **`automationLocatesControlsSemanticallyAndTakesTheNativeClicksWireAndSettlementPath`** (`--fake-sequence --refresh-interval-ms 300`).
  - Pause view is located with `findAll(role: .button, label:)`, which must return exactly one match. It is node 62 and advertises `[ACTIVATE]`.
  - The test then makes four activations of that node: native Pause, automated Resume, automated Pause, native Resume. Before each automated lookup the native button is hidden and its title blanked, so only the semantic tree can find it.
  - A wire tap records every outbound `Event` with its logical class, and every inbound `ServerEventAck`.
  - The four frames have one shape: every field except `event_seq`, `event_id` and `observed_revision` is equal, there are no arguments and `edit_seq` is 0. All four go on the `input` class. Their `event_seq` values are contiguous (1–4).
  - Each automated `observed_revision` equals its handle's snapshot revision. Each native one lies within the revisions published around the click.
  - Every ack has one shape: PROCESSED, with `event_id` and `client_instance_id` echoed, the live `session_id`, and `revision_after_effect` at or past the observed revision. The outbox ends with `pendingCount == 0` and `lastAckedEventSeq == 4`.
  - Measured (`impl1-focused-1.log`): `origins=[native, automation, automation, native] seqs=[1, 2, 3, 4] class=[input ×4] acks=[1:processed, 2:processed, 3:processed, 4:processed]`.
  - The test also writes the full-tree developer report and runs the endpoint check (both below).
- **`aDisabledOrUnsupportedControlRefusesAutomationExactlyAsItRefusesANativeClick`** (`--fake-sequence`).
  - The view is paused natively. Refresh now is then `enabled=false` in the semantic snapshot and in the native button.
  - Automated `activate()` throws `nodeDisabled(63)`.
  - A native click (`NativeActivation.click`, which skips a disabled control as AppKit does) sends nothing. The same interaction is also delivered to the client through `renderer.onInteraction`, standing in for a stale native control. The same `validateSemanticAction` refuses it, silently, because a disabled control is classified as a race, not a contract failure.
  - A Text line (the inspector's first line, located by its text) advertises no event. Automated and native activation give the same `unsupportedAction(56, ACTIVATE)`; the native one arrives through the client's diagnostic hook.
  - Over a 600 ms quiet window there is only the one Pause frame: no frame from any refusal, the outbox `eventSeq` is unchanged, nothing is pending, and the server is still paused.
  - The next automated Resume and Refresh now take `event_seq` +1 and +2, and both settle PROCESSED.
- **`automationSelectsAProcessRowAndReadsTheInspectorSemantically`** (`--fake-source`).
  - The one Table is found by role. PID 4102's ItemId is read from the semantic model that the table node binds (`store.getModelForNode`), not from the native table.
  - The test selects A (4101) natively, then B (4102) with `SemanticNodeHandle.select`. The two `SELECTION_CHANGED` frames have one shape (argument values cleared, property refs equal), consecutive `event_seq`, the same logical class and the same ack shape.
  - The inspector is found by its first line's text and its parent's children. It reads B's four PX-013 lines and the command-line text.
  - The test writes the inspector subtree's report.

### Developer-only inspection output

`SemanticInspectionReport.render` is test output only. It prints the tree to stdout and, when `PX026_EVIDENCE_DIR` is set, writes it to `px026-full-tree.txt` and `px026-inspector-after-selection.txt`.

The report has one line per node: the semantic ID, the registry role, and then label, text, value, accessible description, non-default state, the standard events the node accepts, server-advertised `actions`, `action_key`, `shortcut` and child count. It reads only the T35 snapshot. Two example lines:

```
#62 Button label="Pause view" events=[ACTIVATE] shortcut=primary+alt+p
#5 Table label="Processes" read-only events=[SELECTION_CHANGED] shortcut=primary+l
```

`AutomationClient.expectNoNativeType` checks three things:

- The report names none of the classes the renderer built for this window. The check requires `NSButton` and `NSScrollView` to be among them, so it cannot pass vacuously.
- The report matches no `\bNS[A-Z]…` type name and no `0x` pointer.
- A bounded reflection walk of the snapshot reaches no `NSObject`. Reaching the 500,000-value bound fails the test rather than passing on a partial walk.

### No external endpoint

`AutomationEndpoints.listing()` runs `/usr/sbin/lsof -nP -T s -F ftPnT -a -p <pid> -i` and `-F ftn -a -p <pid> -U` on the test process. It parses lsof's field output, one record per descriptor, and counts as a listener any TCP socket in `ST=LISTEN`, any UDP socket, and any unix socket bound to a path. Output goes to a file and lsof is awaited through its termination handler, never `waitUntilExit()`.

- Before the inspector is made and after the last automated action, the test process had no socket of any kind (`listeners before=[] after=[]; sockets before=0 after=0`). The SSH transport is the `ssh` child's pipes.
- A positive control then opens, lists and closes a TCP listener on 127.0.0.1 and a unix listener under `/tmp`. Both are listed (`PX-026 lsof positive control: …` in the logs), so the empty listing is a finding, not a blind lsof or a broken parser.
- Static check: `git diff b0dfa863 | grep -nE '^\+.*(NSXPCListener|NSXPCConnection|xpc_connection|xpc_|NWListener|CFSocket|NSSocketPort|NSMachPort|bootstrap_|mach_port|\blisten\(|\bbind\(|socket\(|GCDAsyncSocket|HTTPServer)'` (`impl1-listener-grep.log`). Its only hits are that control's `socket`, `bind` and `listen` calls in test code. No product source changed.

### What the tests do not do

- No screen coordinates, mouse events or `NSView` lookups locate a control. The only native views the tests touch are the comparison clicks and selections, and the concealment that defeats a native lookup.
- No srtop- or PID-specific path exists in the client. The PIDs and labels appear only in the test's own assertions.
- No process-changing action exists or was added.
- No retry protocol, secret storage, fleet administration, external listener or SDK attach/detach notice.

## Limitations

- **An automated selection does not move the native highlight.** It is a semantic event: the server inspects B while the native table still highlights A, which the user selected. This is T35's existing behaviour. srtop, as in PX-013, never selects rows server-side. PX-026 makes no claim that the native highlight follows automation.
- **The disabled-control native refusal is unobservable at the client.** The client classifies `nodeDisabled` as a race and reports nothing either way. So "identical" for a disabled control is proved by the same thrown error on the automated path, no frame, no consumed `event_seq` and an unchanged server state on both paths, not by comparing two reported errors. For `unsupportedAction` the two reported errors are compared directly.
- **The lsof check covers this process only.** In a parallel full run, another suite in the same test process could open a listener during the window. The focused and repeated runs, where nothing else runs, are the clean evidence. Mach and XPC services are not visible to lsof; their absence rests on the static grep and on no product source changing.
- **`SemanticAutomationError.description` prints an event TypeRef with the node-type name of the same local ID**, for example `TypeRef(standard:1/Surface)` for ACTIVATE. The cause is the existing `TypeRef.description` precedence, and it is cosmetic: the errors compare by value. The report uses `standardEventName` and is unaffected. Not changed here (out of scope).
- **No external automation surface exists.** That remains future work that needs its own reviewed permission model (§22.9), as the standing contract requires.
