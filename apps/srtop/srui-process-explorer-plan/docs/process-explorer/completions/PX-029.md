## References checked (24 November 2026)

- **K3** `https://man7.org/linux/man-pages/man2/pidfd_open.2.html` (man-pages 6.19, 2026-02-08): `syscall(SYS_pidfd_open, pid_t pid, unsigned int flags)`, glibc provides no wrapper in that page's text; history "Linux 5.3"; errors `EINVAL`, `EMFILE`, `ENFILE`, `ENODEV`, `ENOMEM`, `ESRCH` — no `EPERM`, so an `EPERM`/`EACCES` from it is a filter or security module. Close-on-exec is set on the returned descriptor. `PIDFD_NONBLOCK` (5.10) and `PIDFD_THREAD` (6.9) are not used.
- **K2** `https://man7.org/linux/man-pages/man2/pidfd_send_signal.2.html` (man-pages 6.19, 2026-02-08): `syscall(SYS_pidfd_send_signal, int pidfd, int sig, siginfo_t *info, unsigned int flags)`; history "Linux 5.1"; a NULL `info` is equivalent to `kill(2)`'s implicit `siginfo`; `EPERM` (no permission), `ESRCH` ("the target process does not exist (i.e., it has terminated and been waited on)"), `EINVAL` (another PID namespace); "a PID file descriptor is a stable reference to a specific process; if that process terminates, `pidfd_send_signal()` fails with the error `ESRCH`". The 6.9 `PIDFD_SIGNAL_*` flags are not used.
- **K1** `https://docs.kernel.org/filesystems/proc.html`, Table 1-4: `start_time`, "time the process started after system boot" (field 22 of `stat`, in clock ticks), the field `parse_stat` already reads.
- **Libraries actually used.** `libc 0.2.189` (`libc::syscall`, `SYS_pidfd_open`, `SYS_pidfd_send_signal`, `SIGTERM`, `pid_t`, `c_uint`); no glibc wrapper is called (glibc added `pidfd_open`/`pidfd_send_signal` wrappers only in 2.36), so the binary imports `syscall`, not either name, and the existing nm audit still forbids both names.

## What was built

`apps/srtop/src/handle.rs` (new). Nothing in srtop calls it: the dry-run executor is still the only executor, and the audit refuses any production reference to the module outside it (below).

- **`ProcessHandles::acquire(&ProcessKey) -> Result<HandleId, AcquireError>`.** In order: closes expired handles; refuses `Unsupported(Platform)` where the system has no pidfds (every non-Linux host); refuses `LimitReached` at the bound before anything is opened; requires the key to be from the live `/proc` source (`procfs::live_source_id()`, `procfs:/proc`), a process (not a thread), a known PID, `CreationToken::LinuxBootTicks`, and known boot and PID namespace (`Unidentifiable`); requires the boot to be this one and the PID namespace to be this process's own active namespace (`/proc/self/ns/pid`, the one `pidfd_open` reads a PID in) — `OtherBoot`, `OtherNamespace`; both read once and kept, since neither can change while the process runs. **Then** `pidfd_open(pid, 0)`, and **after** it `/proc/<pid>/stat` again: the start time must equal the key's. The argument the module states: the sampled process held the PID at the scan, before the open; if the open had reached a replacement, the sampled process was already reaped and a process never gets its PID back, so the record read after the open names the replacement's start time or none. A match after the open therefore proves the descriptor is the key's instance. A mismatch is `Replaced`, a gone record `Ended`, an unreadable or unparsable one `Unverified`; each drops (closes) the descriptor. Residue: a replacement started within the same clock tick (10 ms at `USER_HZ` 100) under the same PID is indistinguishable by start time.
- **`ProcessHandles::settle(HandleId, HandleSignal) -> SignalOutcome`.** Removes the handle first, so it is single-use and closed whatever happens; refuses `Expired` at or after its expiry (closed, unsent); otherwise `pidfd_send_signal(fd, SIGTERM, NULL, 0)` on the held descriptor: `Sent`, `Ended` (`ESRCH`), `Denied` (`EPERM`), `Unsupported(NoSystemCall)` (`ENOSYS`), `Failed`. Nothing is reopened or sent by PID. `HandleSignal` is a closed enum with one variant, `Terminate`.
- **Closing.** `cancel` (closes one), `expire` (closes every expired one; also run before each acquisition, and settlement checks expiry itself), `settle` (closes after its one signal), and dropping the table. Descriptors are `OwnedFd`. Bounds: `DEFAULT_MAX_LIVE_HANDLES` 16 per table and `DEFAULT_HANDLE_LIFETIME` 30 s (PX-028's intent lifetime) on `SuspendAwareClock`, so a suspend shortens a handle's life rather than extending it.
- **Unsupported, never weakened.** `open_error`: `ESRCH` → `Ended`; `EMFILE`/`ENFILE` → `DescriptorsExhausted{system_wide}` (reported once, never retried); `ENODEV` → `Unsupported(NoAnonymousInodes)`; `ENOSYS` (`ErrorKind::Unsupported`) → `Unsupported(NoSystemCall)`; `EPERM`/`EACCES` → `Unsupported(Refused)` (a seccomp filter or LSM: `pidfd_open` has no permission check of its own). `ProcessHandles::probe()` opens and closes a handle on this process only, sends nothing, and answers `Ok`, `Unsupported(..)` (actions needing a handle must stay disabled — PX-030 wires that) or a transient error. There is no PID-addressed fallback: the module names no `kill`, and the audit refuses one anywhere.
- **Signals only (acceptance 4).** The module docs and the README state it: a held pidfd makes a *signal* race-free and nothing else; `setpriority`, `sched_setaffinity`, `ioprio_set`, `prlimit` and `/proc/<pid>/...` by path still name a number. This module offers no non-signal operation and no PID-based path; each later family (PX-036..PX-040) needs its own reviewed targeting.
- **The seam.** `PidfdSystem` (`available`, `open`, `read_stat`, `boot_id`, `pid_namespace`) and `Pidfd` (`send`; dropping closes). `LivePidfds` is the host: on Linux the two `unsafe` `libc::syscall` blocks and one `OwnedFd::from_raw_fd` in `mod linux`; elsewhere `available() == false` and no call is made.
- **Small supporting changes.** `procfs.rs`: `live_source_id()` (new, `pub(crate)`), and `read_bounded`, `ended`, `parse_namespace` made `pub(crate)` so the handle re-reads `stat` with the same bounded, identity-safe reader as the scan. `actions.rs`: one module-doc sentence. `lib.rs`: `pub mod handle;`.

## Limitations

- **Not wired.** No action uses a handle. PX-030 wires graceful termination, the support-chain denylist and `probe()`-driven disabling; PX-031 observes outcomes. Until then `Execution`/`ActionOutcome` are unchanged and srtop sends nothing.
- **Same-tick replacement.** A replacement under the same PID that started in the same clock tick as the sampled process cannot be told apart by start time (K1 resolves 10 ms at `USER_HZ` 100). PID reuse that fast needs a full PID-space wrap within one tick.
- **A zombie is the same instance.** A process that exited but is not yet reaped keeps its `/proc/<pid>/stat` and start time, so a handle can be acquired and `pidfd_send_signal` succeeds with no effect; `Sent` never means the process ended (PX-031).
- **`EPERM` at the signal is ambiguous** between the account lacking permission and a filter refusing `pidfd_send_signal`; both are `Denied` and nothing is sent. At the open, `EPERM` can only be a filter or LSM.
- **Stat by path after the open.** The re-check reads `/proc/<pid>/stat` by path, not through the descriptor; the argument above is why that is sufficient for the descriptor's identity, and a failed read fails closed. The scan's PID namespace must be this process's own (`OtherNamespace` otherwise), so a key from a bind-mounted foreign `/proc` is refused.
- **Live coverage.** Permission denial, `ENFILE` and a seccomp-refused call are proved with the fake only (see Tests).
