## Bounded change

- `apps/srtop/src/catalogue.rs` (new): `MetricKey`, `MetricSpec` and `Catalogue`. Each entry carries its `MetricDefinition` (label, source, interpretation; PX-005 to PX-007) plus typed `Unit`, `RawType` (the D1 §6.5 shapes: unsigned integer, string, small typed record), `Origin`, `Aggregation` (`None`, `Sum`, `NonAdditive`), `Formatter`, `DefaultSort`, `Capability`, `Sensitivity`, `CollectionCost` and `RefreshTier`s. `BUILTIN` catalogues exactly the eleven fields already published: `process.pid`, `process.name`, `process.resident_memory`, `process.cpu_usage`, and the seven PX-007 `system.*` figures. - `apps/srtop/src/projection.rs`: each row's cells are `PROCESS_LIST` mapped through `ProcessField::cell`, which holds the exact cell code the projection had (same values, same order).
- `apps/srtop/README.md`: new "Metric catalogue" section. `feature-ledger.px042.json`: four `in_progress` entries.

No dependency, protocol, client or procfs-reader change. `summary.rs` is unchanged: its labels already come from the definitions the catalogue references.

## Design

- **Catalogue shape.** Validation is per entry and then across entries (`Catalogue::new`): well-formed dotted key (≤ 64 bytes), the definition's unit text must equal the typed unit's `describe()`, `Unit::carries(raw)`, the formatter's single accepted `(unit, raw)` pair, aggregation only on a quantity, sort that fits the unit; tier policy (non-empty, no repeats, `Expensive` or `ProcessContent` never `EverySample`, `System` never `OnDemand`); duplicate key; at most `MAX_ENTRIES` (512).
- **Scheduling.** Cheap fields stay in the atomic snapshot read every sample (unchanged path). Expensive fields are only collected through `OnDemandFields::demand(wanted)`, where `wanted` is the complete current set of (process instance key, field) pairs for selected/visible rows: fields not in it are forgotten (never read again), sampled or unknown keys are refused and counted, at most `max_fields` tracked and `max_in_flight` reads outstanding (a stuck read holds one slot until it returns, even after its row is hidden). A field with a value younger than `min_interval` is not re-read.
- **Not blocking the loop.** `demand` only enqueues; `collect_completed` drains a channel with `try_recv`. Production reads run on tokio's blocking pool, as the scan already does.
- **Ordering.** Each read gets a sequence number; a completion is accepted only when it answers the read its slot is currently waiting for, so a read superseded by hide/show is discarded whether it finishes before or after the newer one.
- **Staleness / timestamps.** A value is stamped with the monotonic time its read started (`SourceTime`, distinct from the snapshot's `SnapshotTime`). Stamps must satisfy `issued_at ≤ started ≤ finished ≤ drain time`, otherwise the read is `Failed`. A value older than `max_age` is `Stale`, never `Present`. A value of the wrong raw type for its entry is `Failed`.

## Limitations

- No production field is expensive, so nothing is collected on demand in this revision, and no selection or visible-range signal yet drives `OnDemandFields::demand` (selection arrives with PX-013, visible ranges with the early-scale work). The policy is proven with scripted expensive fields, as the ticket allows; the first expensive collector wires it into the poll loop.
- `Availability` is a vocabulary and mapping; the published cells keep their existing wording (`Unavailable`, `Denied`, `Warming up`). `Unsupported` and `Stale` have no published cell yet, because no current field can be in either state on screen.
- Sorting by the catalogue's `DefaultSort` is PX-009's.
- No Linux container run was repeated: no procfs reader changed, and the projection's output is proven byte-identical by the fixture, scripted and native SSH tests.
