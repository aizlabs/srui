- Standing rules: the chooser changes presentation only. Every column chooser state change is decided by the server; no process is opened, signalled or reconfigured, and nothing the client sends beyond a standard `ACTIVATE` is read.

## Bounded change

- `apps/srtop/src/catalogue.rs`:
  - `ColumnLayout`: a non-empty sequence of distinct `ProcessField`s. The `Default` preset is `PROCESS_LIST`. It provides `hiding`, `showing` (appended after the shown columns, which keep the order the user chose), `moving_earlier`, `moving_later`, `can_hide`, `can_move_earlier`, `can_move_later` and `is_default`.
  - `LayoutError::{Empty, Duplicate}`: a layout naming no column or one column twice is refused.
  - `ProcessField::index`: a column's position among a row's catalogued cells.
- `apps/srtop/src/projection.rs`:
  - `Row.cells` keeps every catalogued cell, in `PROCESS_LIST` order. `Row.value` is those cells projected onto the published layout (`lay_out`, `Row::laid_out`). `SessionItemIds::project` takes the layout. Item IDs and typed sort values do not depend on which columns are visible.
- `apps/srtop/src/sort.rs`: unchanged ordering. `SortValues` already hold every column's typed value, so a hidden sorted column still orders the rows exactly.
- `apps/srtop/src/refresh.rs`:
  - `ProcessView.columns` holds the published layout. Every refresh projects in it.
  - `set_columns`, `restore_default_columns` and `click_column` publish a layout. The plan has four parts:
    - the table's `columns` (`SET_PROPERTY`);
    - the chooser button labels and `enabled` flags that change;
    - `MODEL_UPDATE`s for the rows whose cells change;
    - never a delete, insert, move or recreation of the table or model.
  - When the whole change fits one transaction it commits as one, so headings and cells never disagree on the wire.
  - `columns()`, `column_layout()`, `column_headings()` and `ColumnsError`.
  - `refresh_sort_values` also brings hidden cells up to the latest sample. Showing a column again therefore publishes current values.
  - `SNAPSHOT_SHELL_BYTES` is raised from 4 KiB to 8 KiB for the fourteen new shell nodes.
- `apps/srtop/src/lib.rs`:
  - New shell nodes, between the sort row and the table: `COLUMN_CHOOSER_ROW` (28) and thirteen Buttons (29–41).
    - Per column: `Hide/Show <column> column`, `Move <column> column left` and `Move <column> column right`.
    - `Restore default columns`.
  - `ColumnAction` resolves each click against the server's current layout. A button that could change nothing is disabled, so event validation refuses it. `SHELL_NODE_COUNT` is now 41.
  - `install_column_handlers` installs the thirteen `ACTIVATE` handlers. Each is a bare node constant with `ACTIVATE`, the shape the PX-008 audit admits.
- `apps/srtop/src/main.rs`: installs the column handlers beside the sort and filter handlers.

## Limitations

- R1 manages only the existing cheap columns. There is no expensive-tier column, so the ticket's "enabling an expensive field requests its sampling tier" acceptance item has no field to exercise yet.
- The layout is per session and is not persisted (named saved views are PX-069).
- A layout change too large for one transaction commits as several. The headings commit first, and the cells follow in the next transactions of the same request.
