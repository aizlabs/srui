## Decisions for user sign-off

Reasonable defaults were chosen and are listed in specification section 12. Two of them shape later work and should be confirmed:

1. **A2 — Split on the dashboard's critical path.** Options: (a) *recommended*: keep PX-070-G02 as a prerequisite of PX-073-G01 so the user can drag the panel/table divider; (b) limit local resizing to window resize, graph reflow and compact/expanded presentations, drop PX-070-G02 from PX-073-G01's `depends_on` and keep it as optional generic work. (b) removes one registry change from the dashboard path.
2. **A3 — how Split names its axis.** Options inside PX-070-G02: (a) *recommended*: one registry property `split_axis` with enum `SplitAxis` (`side_by_side`, `stacked`), refused on other types, like PX-016-G01/PX-017-G01/PX-018-G01's registry additions; (b) a fixed axis, no registry change, which cannot express both a stacked dashboard and a side-by-side split; (c) two node types, which contradicts D1's single `Split`. Any of these is a protocol/registry decision made in PX-070-G02, not here.

The others (A1 btop v1.4.8; A4 compact panels reuse the PX-070 meters; A5 bytes per second, never bits; A6 budgets and thresholds are design maxima to be measured; A7 the btop binary only in the disposable devbox) are defaults within this ticket's scope.
