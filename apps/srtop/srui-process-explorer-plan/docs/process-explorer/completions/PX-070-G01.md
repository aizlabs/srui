## Verification round 1 follow-up (logs prefix `impl2-`)

Verification round 1 passed on `340d7657` with four findings, fixed in a separate commit (not an amend):

- **F1 (low): the snapshot reserve counted only host series in the profile encoding.** Specification section 7 now charges everything a catch-up snapshot carries, because an extension node travels with its fallback subtree (§11.1). The fallback is bounded at `MAX_FALLBACK_SAMPLES` = 60 samples per series and `MAX_FALLBACK_ROW_BYTES` = 64 bytes per row (section 5). PX-090 inspector history (4 processes × `MAX_HISTORY_SERIES_PER_PROCESS` 4 × 900 samples) is charged to its own `HISTORY_RESERVE_BYTES`. Arithmetic, at 24 bytes per sample:
  - `DASHBOARD_RESERVE_BYTES` = 1,179,648. Its sum is 1,119,136: 842,400 for host series (39 × 900 × 24), 149,760 for host fallback rows (39 × 60 × 64), 65,536 for device rows (2 × 64 × 512) and 61,440 for nodes (96 × 640).
  - `HISTORY_RESERVE_BYTES` = 458,752. Its sum is 407,040: 345,600 for series (4 × 4 × 900 × 24) and 61,440 for fallback (4 × 4 × 60 × 64).
  - Total 1,638,400 bytes.
- **F2 (low): Disk and Network had ≤ 16 nodes but up to 16 device series.** One PX-071 graph node per panel now carries the aggregate and every expanded device's series, at least `MAX_SERIES_PER_GRAPH` = 18. Its Standard Widget fallback is one model-backed `Table` of recent samples, whose rows name the series. Node counts therefore no longer grow with expansion, and per-device history (not only current rates) has an accessible alternative.
  - This is now a PX-071 requirement: one sentence appended to PX-071's build text, and PX-071 depends on PX-070-G01. Both were changed in `task-index.json`, the ticket, the master block and the catalogue together.
- **F3 (info): the reserve lowers the row ceiling.** Measured, not estimated. I ran `git archive HEAD` of `340d7657` into a scratch directory outside the repository with `CARGO_TARGET_DIR` there as well, and ran `cargo test --locked --manifest-path apps/srtop/Cargo.toml --test meters_test a_high_core_count_host_stays_bounded_in_every_layout -- --nocapture`. Results:
  - Unchanged copy: 25,564 rows, snapshot 14,500,426–14,500,438 bytes (`impl2-row-ceiling-baseline.log`).
  - With `METERS_RESERVE_BYTES` raised by 1,638,400 in that copy only: 23,055 rows for every CPU count, snapshot 13,075,303–13,075,315 bytes (`impl2-row-ceiling-with-reserve.log`). That is 2,509 fewer rows.
  - Both runs exit 0. Specification section 7 tells PX-073-G01 to re-baseline the row-ceiling assertions. No repository file was built against or changed by this measurement.
- **F4 (info): PX-095.** PX-095 is now an explicit dependency of PX-073-G01 (alias `multihost`), changed in `task-index.json`, the ticket, the master block and the catalogue (A8). The execution order already had PX-095 before PX-073-G01.

## Limitations

- **Specification only.** No dashboard behavior exists; every budget and threshold is a design maximum (A6) that PX-073-G01 and PX-073-G02 must measure and assert. A failed threshold keeps R-Dashboard open; raising one needs an amendment recorded before the rerun.
- **Accessibility grouping not verified.** Whether a labelled `Row`/`Column` is exposed as a native accessibility group was read from code, not tested; PX-073-G01 verifies it on a real window.
- **PX-071 fixes the series encoding.** The reserve arithmetic assumes at most 24 bytes per sample and 64 bytes per fallback row; PX-073-G01 recomputes it from PX-071's real encoding. The 23,055-row ceiling was measured by raising an existing reserve in a scratch copy, not with real dashboard nodes.
- **No btop run.** The pinned binary's digests are recorded from the release metadata; nothing was downloaded or executed. PX-073-G02 runs the comparison.
- **Upstream drift.** btop's `main` (`fdf7fba4`) is ahead of the pin; the pin does not follow it.
