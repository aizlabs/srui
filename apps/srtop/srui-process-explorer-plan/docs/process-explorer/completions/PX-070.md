## Design decisions

- **Meters are the PX-007 summary figures.** srtop had no other meter. The families are CPU (overall), Memory, Swap, Load, Uptime and Processes, keyed in settings by their metric IDs (`system.cpu_busy`, …). The freshness line is not a meter: it says how stale every figure on screen is, so it is always shown, even with the meters hidden.
- **Two semantic groups.** `MAX_METER_GROUPS = 2`, like htop's two header columns: standard `Column`s in a `Row`. The client decides where they go and how they wrap; a narrow window scrolls the row horizontally (the generic client's own Row-in-Column behaviour).
- **Presentations.** Bar (a `Progress` beside its line) for CPU, Memory and Swap; Text (the line alone) for every meter. A bar is never shown without its line, so every value has a textual fallback.
- **Every node exists in every layout.** A node ID is never reused in a session (§6.2; the first implementation deleted and recreated hidden meters and the store refused it, `NodeId(8) has already been used`). Hiding a meter, or showing it as text, moves the meter, or the bar, into a collapsed container `METER_HIDDEN` (107). A layout change is therefore a run of `MOVE_NODE`s, never a create or delete, and the shell's node count is constant (111).
- **Hidden nodes are frozen.** A sample updates a meter's nodes only while the meter is shown (a bar only while shown as a bar) and the meters are shown. Otherwise they keep what the client holds, and a layout change that shows them again brings them up to the current figures in the same revision. A meter that stays shown keeps exactly what the client holds through a layout change: the change re-sends no figure.
- **Hiding the meters** collapses both groups and the row of groups (`SET_PROPERTY visibility`), with no move.
- **Controls.** One Row of 23 standard Buttons and a status Text (108–132) under the summary: per meter Hide/Show, Move earlier, Move later; for CPU, Memory, Swap a bar/text button; Hide/Show meters; Restore default meters. Moving crosses the group boundary at the ends. A button that could change nothing is disabled, so event validation refuses it. Disabled in the shell that collects nothing.
- **Saved preference.** The layout is part of a saved view (PX-069), so it is per view and per source. Settings format version 3 adds `meters on|off` and two `meter-group` lines per view.
- **No per-CPU expansion here.** srtop has no per-logical-CPU collector; PX-052 owns it ("per-logical-CPU measurements … more than 256 CPUs"). The CPU meter is one aggregate over every CPU the source lists, so the high-core-count fixture proves that a host with 65,536 CPUs publishes the same nodes and the same row ceiling as one with 4. A later per-CPU meter is a collection model (T28), not a node per CPU; this is recorded in the module doc and the README.
- **Remount on a layout change.** The generic client remounts its native views on any structural transaction (`LayoutRenderer.apply`). A layout click is structural by design, so it rebuilds the window's views once; samples never do. Improving the generic client to apply moves in place would be a generic renderer facility and is out of scope.

## Limitations

- **Per-CPU meters are not offered.** They need PX-052's per-logical-CPU collector. The CPU meter is an aggregate, so CPU count cannot grow the summary; the virtualized-list requirement applies when a per-device meter exists.
- **A layout change remounts the native window.** The generic client remounts on any structural transaction, so each layout click rebuilds the native views once (the table keeps its selection through the client's selection memory). Samples never remount. In-place structural application is a generic renderer change, not this ticket's.
- **Hidden meters are frozen, not removed.** They stay in the store (collapsed) with the figures they last showed, so a catch-up snapshot carries them: bounded, inside the summary's fixed 8 KiB reserve.
- **The layout is saved only with a view.** Like columns, changing the layout without saving a view is session-only, and a restart applies the active view's layout.
- **Hiding a text-mode bar meter is two moves** (its row, and its bar back into the row it will show next).
- **No graph or indicator mode.** PX-071–PX-073.
- **Narrow windows.** The row of groups scrolls horizontally rather than stacking: that is the generic client's Row-in-Column rule, client-local by design.
