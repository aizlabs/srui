## How the specification was checked

The checker is not repository code. It lives in the run's `PX-071/` scratch directory; logs carry the prefix `impl1-`.

- **Fixture checker** (`metrics_fixture_check.py`). It is an independent reference implementation of the section 10.1 rules, written in Python with no UI dependency. It parses every fixture and expands the shorthands. It then applies each setup and each case atomically twice: once as a client that implements the profile, and once as a base client (generic store plus the §11.1 mount rule). For every case it asserts both expected outcomes. For every accepted state it recomputes the fallback rows the server must publish (F1–F4: series-major order, newest 60, cell bytes, row bytes on the wire, formatting) and compares them with the fixture's rows. It also checks the negotiation table and the formatting and duration parity tables.
  - Result: `{"fixtures": 8, "transactions": 16, "case_outcomes": 131, "negotiation": 9, "formatting": 34, "skipped": 1}`, PASS. The one skip is the base-client outcome of `partial-reset`. A base client treats that operation as an ordinary sparse range reset, which the checker does not model, so it is not asserted.
  - Log: `impl1-fixture-check.log`.
- **Mutation check of the checker** (`impl1-checker-mutants.log`). Each of 24 single-rule mutants removes or weakens one rule, or one formatter or fallback detail. Every mutant makes at least one fixture expectation fail: 0 survivors.
  - A first run had two weak spots, both fixed before the final run. `S1-shape` survived because no case had a non-Table fallback backed by a Table model, so `graph-fallback-is-a-list` was added. `F4-duration-floor` survived because no duration distinguished floor from rounding, so the 29-minute row was added. One mutant spelling was invalid Python and was rewritten.
- **Encoded sizes** (`sizes.sh`, `impl1-encoding-sizes.log`). Measured with `protoc --encode` (libprotoc 29.3) against this checkout's `protocol/srui.proto`, every field at its cap:
  - sample item 20 bytes inside an operation; gap item 13;
  - fallback row 64 (the checker's own encoder gives the same 64);
  - descriptor 474;
  - `SeriesGraph` node 1,167; `Gauge` node 1,060;
  - per series per sample 114 bytes typical and 157 worst.

## Findings for later tickets

- **PX071-F1 (budget, open).** With every panel expanded and 8 devices and 8 interfaces showing series, the series and their mandatory fallback rows alone come to about 4,446 B/s (39 × 114 bytes). dashboard.md section 7 bounds that configuration at 4 KiB/s, and PX-073-G02 uses the bound as a pass/fail threshold. The fallback rows are 77 of the 114 bytes per series per sample, and the dashboard itself requires them (exact sample values, always carried). This ticket does not change dashboard.md. The dashboard owner must amend the bound or the measured configuration before PX-073-G02 runs, and PX-073-G01 measures the real figure. The default layout is about 342 B/s. Specification section 7.3.
- **Reserves still hold.** dashboard.md section 7 assumed at most 24 bytes per sample; the real figure is 20.
  - Host side: recomputed with descriptors, models, operation headers and graph nodes, the profile's share of `DASHBOARD_RESERVE_BYTES` is at most 1,002,104 of 1,179,648 bytes.
  - History side: 364,052 of `HISTORY_RESERVE_BYTES` 458,752.
  - PX-073-G01 still recomputes from real nodes. Specification section 7.2.
- **No wire model deletion.** SRUI has no `DELETE_MODEL` operation, so each graph owns 18 fixed sample-model slots that it reuses, and a session may create at most 16 graphs (320 profile models). A generic deletion operation would be a separate protocol ticket. Specification section 4.3.
- **Enforcement hook.** If the Rust store or the Swift applier has no hook for an extension's apply-time rules, PX-072/PX-073 add it as a narrowly scoped prerequisite with conformance tests. Specification section 10.2.
- **Base-client opacity.** That a base client stores profile models and properties opaquely was read from code (`SemanticStore.createModel`, `SemanticStore::set_property`, `standardPropertyValueType` returning `nil` off namespace 0), not tested. PX-073 tests it.

## Limitations

- **Specification only.** No profile behavior exists. Every limit and size is a design value that PX-072 and PX-073 must implement and assert at and past each bound. The fixtures are documentation in a semantic notation. They are not wire vectors and are not wired into any test suite. PX-072/PX-073 turn them into Rust and Swift tests.
- **The reference checker is scratch evidence.** It shows that the rules are consistent with the fixtures and implementable without a UI toolkit. It is not a third supported implementation and is not committed.
- **Decision A1 (the canonical name) needs review.** It was chosen in this ticket from the project's GitHub organization. Renaming costs nothing until PX-072 ships a session that advertises the profile.
- **PX071-F1 is unresolved here** by design: it belongs to the dashboard specification.
- **Formatting parity** between Rust `format!` and Swift `String(format:)` on ties is specified (ties to even on the exact binary value) and tabled, not executed in either language here.
